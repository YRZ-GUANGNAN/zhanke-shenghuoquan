# 交付报告模板

交付、汇报阻断或记录复杂验收时读取本文件。按风险和仓库惯例选择详略，不为每个小改动创建一套报告文件。字段需要根据真实证据填写，缺少证据就写未执行或阻断。

## 轻量交付

用两到三段说明：

1. 用户可见的结果，以及实际变更文件或产物入口。
2. 已执行的验证、结果及环境边界。
3. 仍需处理的事项；已授权提交或推送时附真实提交与远端链接。

示例语气：

> 已修复重复点击导致的重复提交，刷新后显示服务端确认的状态。相关回归和客户端构建通过。双设备验证尚未执行，因此本次不对另一端接收情况作结论。

## 跨模块交付

仅保留适用字段：

| 字段 | 填写内容 |
| --- | --- |
| 目标 | 本轮用户期望完成的动作与结果 |
| 基线 | 分支、起始提交、候选提交；没有提交时写明工作区状态 |
| 范围 | 实际改动模块、契约及明确保留的边界 |
| 实现 | 各端当前行为及关键设计取舍 |
| 证据 | 检查或操作、环境、时间、产物引用和结果 |
| 阻断 | 已失败或缺少前提的项，以及阻断哪个交付阶段 |
| 残留 | 测试数据、文件、服务、云对象与处理状态 |
| 交付 | 本地入口、提交、推送或部署状态，按实际发生填写 |

## 验收矩阵

使用 `检查项 / 提交或产物 / 环境 / 执行方式 / 观察结果 / 状态 / 证据` 作为列。环境可描述为隔离测试、本地应用、指定集成环境、真机或生产，不写凭证。

下面是判定示例，不是本任务的测试记录：

| 检查项 | 实际观察 | 应记录的结论 |
| --- | --- | --- |
| 客户端构建 | 编译退出码为 0 | 构建 `PASS`；未证明页面交互正常 |
| 安全测试入口 | 隔离用例通过，真实服务用例跳过 | 隔离测试 `PASS`，真实集成 `NOT_RUN` |
| 数据库写入 | 指定环境因字段漂移而失败，新建隔离库可通过 | 指定环境 `FAIL`；隔离结果不能覆盖它 |
| 多账号消息 | 单端提交成功，另一端未操作 | 发送接口 `PASS`；接收与双端流程 `NOT_RUN` |
| 线上健康 | 服务返回正常，但未部署候选版本 | 当前服务健康；候选上线 `NOT_RUN` |
| GitHub 推送 | 远端分支指向本次提交 | 推送 `PASS`；未推断 PR 已合并或应用已上线 |

## 根因与阻断

存在问题时把以下内容连接起来，不把猜测写成原因：

- 触发条件和真实错误发生的阶段。
- 最小复现、日志或数据差异。
- 已证实的原因，以及仍待核实的假设。
- 最小可行修复及需要保护的兼容行为。
- 本轮已完成的独立工作。
- 解除阻断所需的具体权限、数据、环境或用户决定。

无法测试时给出可执行的下一步，例如需要哪种设备、哪个环境的访问权限或哪份真实配置；不要仅写“请人工验证”。

## 残留记录

对每类本次资源记录 `归属标记 / 清理前 / 清理后 / 保留原因 / 处理机制`。数量未知时写未知，不能填 0。允许按保留期或 GC 继续存在的对象应明确说明。

如果只有一个无副作用的文档改动，说明没有创建运行资源即可，不制造数据库或云对象检查任务。

## 证据卫生

报告保留可复核的方法和必要引用，去掉 token、签名 URL、密钥、连接字符串与私人数据。演示、夹具、历史截图和推演必须标明；不能制造命令输出或将预期结果充当执行日志。

提交报告只描述本次已知状态。其他用户改动仍存在时说明已保留，不宣称整个工作区干净；没有远端确认时不宣称推送完成。
