# 验收清单

在开始测试、评估是否可交付或准备发布时读取本文件。选用与改动有关的项；不要求每次任务执行全部检查。项目明确要求的检查仍须执行，无法执行时记录原因。

## 选择检查范围

| 变更类型 | 最小有用证据 | 何时扩大 |
| --- | --- | --- |
| 文档或 skill | 格式可解析、引用存在、描述和正文一致，无未完成占位 | 影响 agent 决策时用真实场景检查越权、误触发及证据判断 |
| 样式与布局 | 相关构建、目标尺寸截图、关键操作回归 | 触及路由、数据、权限或共享组件时检查受影响业务 |
| 客户端真实读写 | 类型检查、成功与失败响应、重试、刷新后状态 | 跨端消费相同契约或包含持久化副作用时做集成回归 |
| 状态机、权限、资金 | 正常、越权、过期版本、重复请求、并发和错误路径 | 涉及外部支付或异步回调时验证幂等、恢复及审计 |
| schema 或迁移 | 当前结构对照、升级兼容、启动后结构、回退或修复策略 | 已有环境漂移时单独确认对齐范围，不以新库通过替代 |
| 发布准备 | 仓库必要检查、候选构建、配置及产物扫描 | 发布后核实部署版本和关键业务路径 |

## 运行前

- 查命令的实际实现与工作目录，区分隔离测试、集成测试、种子初始化和迁移。名字含 `test` 不代表只读。
- 确认测试使用的环境变量来源，避免继承生产凭证后误连共享资源。可以报告变量名和缺项，不输出值。
- 核实测试目标、可写范围、数据标记和清理方式；涉及外部写入时核对授权。
- 大构建或跨目录测试前检查空间、依赖与进程，防止环境错误被误记为业务回归。
- 对部署和数据库变更核实恢复手段，先完成可逆的本地准备。

## 行为证据

不要只检查页面存在或按钮可点击。依据实际业务验证以下变化：

- 操作前后服务端状态、持久化结果与界面一致；刷新或重新进入仍正确。
- 正常用户能完成主路径；无权限身份不能通过修改 URL、对象 ID 或直接请求绕过限制。
- 相同意图重试不重复创建、扣款或触发通知；重复提交与新的业务意图能区分。
- 过期状态或版本号导致明确冲突，不悄悄覆盖其他人的更新。
- 失败、超时、空数据与协议错误有可辨识结果，不返回伪造成功或把错误吞成空列表。
- 多端交互分别验证两端。单端出现消息气泡不能证明对方收到，接口成功也不能替代设备行为。
- 媒体、审核或异步任务验证最终状态和不可见状态，不能只看首次请求成功。

## UI 与产物

- 以目标平台实际渲染为依据，查看桌面或窄屏、长文本、大数值、加载和失败状态。
- 检查固定区域、滚动容器、弹窗、键盘、安全区、点击范围和返回路径。
- 图片、图标、字体与真实内容实际加载；截图用于展示布局，交互记录用于证明流程。
- 生产候选使用指定环境构建；扫描产物是否混入开发地址、mock 路径、密钥或失效入口。
- 写明候选版本与提交。不要把旧截图、旧产物或其他分支服务当作本轮证据。

## 环境差异与冲突

发现文档、迁移、运行时结构或测试入口不一致时，记录差异属于哪个提交、环境和时间。追查启动钩子、自动迁移、人工变更或配置差异，只有证据支持时才判断根因。

本地隔离环境通过只说明那个环境通过。指定验收环境失败时保留 `FAIL` 或 `BLOCKED`，不要切换到新建空库后宣称原问题已解决。可继续完成不受影响的代码检查和报告。

测试入口跳过真实外部服务时，记录跳过范围；不能把“命令返回 0”解释成所有集成测试都实际执行。需要当前证据时检查缓存和跳过条件。

## 状态定义

| 状态 | 含义 |
| --- | --- |
| `PASS` | 在注明的提交和环境下实际执行，并满足该项验收条件 |
| `FAIL` | 已执行，观察结果不满足条件 |
| `BLOCKED` | 已确定缺少环境、权限、数据或其他前提，无法完成此项 |
| `NOT_RUN` | 未执行，不对结果作推断 |
| `N/A` | 与本次范围不相关，并说明为何不适用 |

按项汇总后再判断整体是否满足当前目标。某个必要发布项仍阻断时，可以说“代码检查通过，发布阻断”，不能以“有条件全部通过”抹去差异。

## 残留与发布后

记录本次创建的临时数据、对象版本、文件和服务；只处理可识别且在授权内的目标。需要保留给用户试用的服务写明入口，不能擅自关闭。受保留期、供应商限制或标准 GC 管理的资源说明状态与后续处理，不以越权强删换取零计数。

GitHub 交付核实远端仓库、分支和提交。应用发布另外核实部署或上传版本、关键路径与错误情况。平台审核、合规登记、设备验收按各自权威状态判断；它们不由代码构建结果推导。
