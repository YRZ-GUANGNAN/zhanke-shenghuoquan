# 2026-11-13 上线门禁与模拟数据类实际验收

本记录区分代码级上线门禁、隔离 MySQL/HTTP 模拟验收和真实外部平台验收。
本轮没有向生产数据库写入模拟数据，也没有发起真实微信支付、退款或通知。

## 完整上线门禁

`npm run verify:release` 顶层退出码为 0，覆盖：

- 前端排版、手势、刷新、媒体、身份、钱包、商家和骑手工作台契约。
- Admin/MiniApp TypeScript 类型检查。
- Go 全量安全测试、fresh 全量测试和 `go vet ./...`。
- 商家资金、骑手资金/结算/广播/提现、通知三套隔离 MySQL 验收。
- 6 组真实 HTTP + MySQL 模拟业务场景，SKIP=0。
- 骑手发布预检 31/31、离线恢复演练 17/17。
- MiniApp 和 Admin 生产构建。
- `git diff --check`。

MiniApp 构建主包 1,565,542 bytes，总包 2,180,468 bytes，仍在微信包体限制内。
Webpack 仍输出既有 CSS 顺序建议和体积建议警告，未影响构建退出码。

## 模拟数据类实际测试

新增 `npm run test:release-simulation`，使用独立 MySQL 8.4 实例执行全部 56 个迁移，
再通过真实 Gin HTTP 路由、GORM 仓储和 MySQL 事务运行以下场景：

1. 配送建单、商家所有权、幂等、费用快照和商家/骑手身份门禁。
2. 双骑手抢同一订单和并发容量控制，验证只有一次成功。
3. 配送状态推进、outbox、里程碑时间和读取隔离。
4. 商家钱包充值、钱包支付、余额扣减、订单资金读取和退款接口。
5. 测试专用退款 adapter 返回微信“受理中”，验证本地状态机不把受理中写成已到账。
6. 私密配送凭证仅商家、当前骑手可见，外部账号和已释放骑手不可见。
7. 身份迁移 apply → rollback → apply，以及真实 HTTP 身份切换和持久化。

结果为 `RELEASE_SIMULATION_SCENARIOS_PASS=6`、`RELEASE_SIMULATION_SKIPS=0`；
身份临时数据库残留为 0，隔离 MySQL、临时目录已清理，既有 MySQL 服务未被修改。

## 本轮发现并修正的验收问题

- 服务页已删除营业状态后，学生入口契约仍在检查旧变量 `filteredMerchants`；已改为验证当前
  `status === 'empty'` 和真实商家列表状态，不修改页面业务实现。
- D3 资金 HTTP 测试夹具仍以学生身份访问商家路由；现改为通过真实身份服务切换至已批准商家，
  继续验证中间件二次资格复核。
- D3 微信退款场景原先错误依赖未配置的本地 provider；现使用仅限测试的 adapter 模拟
  `PROCESSING`，并明确不代表真实微信退款成功。

## 验收边界

- 模拟成功不等于生产真实交易成功。
- 未发起真实微信支付、真实退款、微信订阅消息或真实 IM 消息。
- 未执行生产数据库写入、生产迁移、开关变更或部署。
- 微信真机支付、取消/退款到账、通知栏收件与点击、次日结算、相机上传和视觉验收仍需外部现场证据。
