## 优先补充

| 优先级 | 已确认现状 / 风险 | 建议与验收条件 |
|---|---|---|
| P1 | 字体全部随 rpx 线性放大缩小；没有统一的可读下限和大屏上限 | 字号与内容列宽分离，先确定正文/评论/辅助文字上下限；正常字号、大字号分别验收，不能用全页缩放冒充系统大字体 |
| P1 | 导航与发布没有独立的 44px 触控底线 | 视觉图标保持现有尺寸，外层点击区至少 44×44px；不通过放大“＋”字形解决；核对全部入口显示和部分入口关闭两种布局 |
| P1 | 二手私聊只抬升固定输入栏，消息滚动区的底部预留不随键盘高度变化 | 验证最新消息与发送按钮都在键盘上方；选择窗口高度重排或单一键盘高度管理，避免微信自动顶起与手动 bottom 重复补偿 |
| P1 | 帖子评论、二手留言和配送聊天的键盘处理方式不一致 | 先分别核对当前微信原生 `adjustPosition` 行为，保留草稿、回复目标与发送状态；收键盘后可继续滚动和点击 |
| P1 | 公共 CapsulePageHeader 只在 React 渲染时读尺寸，首页等没有统一窗口变更订阅 | 统一窗口/安全区快照，在 resize、恢复前台时刷新；详情图集继续沿用已有正确的重算逻辑；订阅解绑，避免每个组件重复监听 |
| P2 | 大屏没有统一内容最大宽度；没有显式的横屏/可调整窗口策略 | 明确支持的显示方式，再决定居中内容列、左右安全区与固定栏对齐；不只增大卡片、字号、图标，也不直接复制 Android 设备品牌名单 |
| P2 | AppDialog、AppActionSheet 在 visible=false 时直接 return null，仅有进入动画 | 补退出阶段与结束卸载；快速开关、退出中再打开、卸载都取消旧任务；业务确认只执行一次，关闭动画不修改业务状态 |
| P2 | 减少动效覆盖不完整，图集页码、部分导航/设置反馈未统一 | 按组件补齐 transform/opacity 降级；微信是否响应该媒体查询需要真机确认；加载状态仍清楚，不要求整页持续动起来 |
| P2 | 透明遮罩模糊、骨架渐变有绘制成本；没有覆盖完整动作的性能采样 | 先测中低端 Android 的列表滚动与弹层，再决定降级；不使用参考录屏平均 FPS 声称本产品稳定 60/120Hz |

## 最新资料能支持什么

- `docs/深度研究/动效/motion-findings.md`、`metrics-summary.json`：单台魅族21/Android16 的观察。图集页码约 200ms 淡入、完成后等待5000ms、约200ms淡出；这一局部已有实现与计时回归。不要给微信原生导航叠第二套约200/300ms整页动画。
- `docs/离线补全/第二轮/01-窗口尺寸与设备条件.md`：窗口、物理屏幕、内容容器不可混用；Android分支及设备名单不是微信适配实现。
- `docs/离线补全/第二轮/02-字体默认与条件覆盖.md`、第三轮字体表：默认值与条件覆盖分开；不能把参考16sp/15sp宣称所有机型最终字号。
- `docs/离线补全/第二轮/03-模拟器宽度与返回观察.md`：改变窗口与重进页面会有不同结果，需要分别验证。当前产品图集已有 resize 接入，不应照搬参考应用的旧高度现象。
- `docs/模拟器补测/第五轮/01-长评论状态与改宽.md`：正文展开、回复列表展开、面板打开、图片返回、窗口变化是独立状态；不能从单条样本推全局折叠阈值。
- `docs/离线补全/03-真机补测执行表.md`、`04-模拟器可用性与测试边界.md` 和渲染管线报告：键盘、边缘返回、系统字号、前后台和性能仍需独立采样。参考库没有替本产品完成这些验收。

| iOS 刘海/灵动岛/底部手势区 | 自定义导航、固定操作栏、封面编辑、输入 | 未完成实体机验收 |
| Android 手势与三键导航 | 留言、私聊、配送聊天，安全区切换 | 未完成实体机验收 |
| 默认字号与系统较大字号 | 正文、作者、回复归属、价格/计数、弹层 | 当前只有固定字号与rpx模型；系统条件待测 |
| 低高度横屏、平板分屏、折叠屏展开/收起 | 同页面变化与退出重进分别验证，键盘开闭各一轮 | 768仅布局模型，不代表平台已支持或已验收 |
| 60/120Hz、中低端机 | 连续滑动、开关弹层、图片加载、快速点赞 | 没有真实设备性能结论 |
| 弱网、断网重试、切后台返回 | 保留草稿/筛选/锚点，禁止重复提交与旧回调覆盖 | 需在隔离测试和真实微信分别验证 |

建议先解决可读性、触控区、键盘与窗口重算，再补退出动画和按压细节。保留蓝色主题、已有咨询页面、真实接口权限和功能开关；不增加视频、直播、评论图片或第三方视觉资产。
