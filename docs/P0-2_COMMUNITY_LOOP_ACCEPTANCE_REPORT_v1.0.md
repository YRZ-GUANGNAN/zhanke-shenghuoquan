## 3. 数据与一致性整改

- 新增 `user_follows(follower_id, followee_id)`，复合主键防止重复关注，并提供 followee 索引。
- 新增 `notifications`，事件唯一键防止重试产生重复通知；查询索引覆盖 recipient、read_at、created_at。
- 评论通知只在统一审核流把评论改为 approved 后产生，不向帖子作者暴露未审核内容。
- 自己评论/点赞自己的帖子不生成通知；自己关注自己在 service 层拒绝。
- 通知列表和已读更新都强制携带当前 recipient ID，不能读取或修改他人通知。
- 修复并发点赞的 `ON CONFLICT DO NOTHING` 后仍重复加计数问题；只有真实插入关系时才增加计数。
- 收藏也改为冲突幂等插入，避免并发重复键错误和计数漂移。
- 评论状态使用行锁；approved → rejected 会回退 `comment_count`，重复 approved 不重复加计数。

数据库变更位于 `005_community_loop.sql`，同时更新全新安装基线 `001_init.sql` 和 Gorm 模型。
