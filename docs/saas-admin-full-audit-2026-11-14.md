# 码里码外 SaaS 后台全站审查报告

日期：2026-11-14

审查对象：`https://saas.malimawai.cn/IT5rPA4GoLM0zh4NTx62P2RPbapUE7`

## 1. 审查结论

目标后台是一个面向“校园生活服务类小程序”的 SaaS 运营后台，围绕“站点 + 订单 + 接单员”的资金与履约闭环展开，同时提供完整的用户、审核、营销、广告、小程序、服务号、素材、通知与平台级配置能力。

整体信息架构清晰、业务闭环完整，但**界面是传统工具型后台**：以表格 + 筛选 + 批量操作为主，视觉与交互都较朴素。审查为本地复刻确认了以下事实：

- 一级菜单 21 项（含“上线流程”和超管专属的“高级功能/插件应用”），二级页面 70+ 条前端路由。
- 后台 API 500+ 条，说明大量页面具备真实增删改查、审核、导出、批量处理能力。
- 核心业务线：用户 → 站点/类型/费率 → 订单/资金走向 → 接单员/派单/结算 → 提现审核；营销线：次卡、优惠券、积分、签到、拉新；运营线：私信、广告、素材、通知、协议与系统设置。
- 视觉主题为“浅色 + 紫色强调”（主色约 `#955ce6`，选中菜单底色约 `#f9f0ff`），组件语言为 Ant Design Vue 风格。

本报告只做事实审查，不包含任何真实用户信息、手机号、Webhook 地址或密钥。

## 2. 证据与方法

三种证据来源，结论中分别标注：

1. **页面观察（运行时）**：用已登录会话逐个打开页面，记录可见标题、按钮、表格列、表单字段、Tab、空态与分页行为。
2. **静态代码推断（前端包）**：下载站点引用的 5 个 JS 包（约 5.8 MB），提取菜单 `key` 路由与 `/admin/...` API 路径。静态路径只代表代码声明，不代表页面当前全部开放。

## 3. 技术识别（静态代码推断）

- SPA 前端：Vue 2 风格编译产物 + Ant Design Vue 组件（`a-menu`、`a-table`、`a-modal` 等渲染痕迹）。
- 网络层：axios 0.21.4 痕迹，API 统一挂在 `/admin/...` 下。
- 静态资源域名：`media.malimawai.cn/saas/admin/`。
- 路由模式：history 风格路径（如 `/user/users`、`/config/webhook`），新增页有独立子路由（如 `/notice/msg/add`）。
- 登录：账号 + 密码 + 图形验证码；登录页含“忘记密码”与初始化/重置路由。
- 登录后可见“工作台 / 帮助中心 / 站点切换 / 消息通知 / 下载客户端”等全局能力。

## 4. 全局框架（页面观察）

布局为左侧菜单 + 顶部栏 + 内容区：

- 顶栏：帮助中心、工作台入口、通知铃铛（带未读计数）、下载客户端、账号区。
- 侧栏：站点标识 + 可折叠菜单，分组含业务运营、平台配置等；菜单项带图标，子菜单可展开。
- 内容页头部：标题 + 说明 + 刷新/操作按钮。
- 列表页统一模式：搜索区（多个输入 + 取消/搜索）→ 操作区（新增/导出/批量）→ 表格（全选/编号/状态/时间/操作）→ 分页（页码 + 跳页）。
- 配置页统一模式：Tab 分组 + 表单 + “提交保存”按钮。

## 5. 视觉系统（页面观察 + 计算样式）

- 背景：白色 `#fff`；正文色 `#333`。
- 主色（按钮/链接）：约 `#955ce6` 紫。
- 选中菜单底色：约 `#f9f0ff`。
- 圆角：按钮约 8px，卡片/表格圆角较小。
- 字体：`-apple-system, Segoe UI, PingFang SC, Microsoft YaHei` 等系统字体栈。
- 组件：Ant Design Vue 默认风格，表格头浅色，状态用彩色文字/圆点徽标，空态显示“No Data”插画。
- 数据可视化：数据总览含曲线图、年龄分布、设备分布、排行榜等图表。

## 7. 跨页面交互模式（页面观察）

- 列表页：搜索区“取消/搜索”成对出现；操作区常见“导出 / 批量 / 新增”；表格首列复选、尾列操作（编辑/详情/封禁/审核等）。
- 弹窗表单：新增/编辑使用弹窗或独立子路由；按钮多为“取消/确定”或“返回/保存”。
- 状态体系：启用/禁用、审核通过/拒绝、订单多阶段状态、提现处理状态。
- 空态：“No Data”插画 + 共 0 条数据；加载态：表格加载图标；错误态：接口失败提示。
- 敏感配置：密钥类字段仅输入框或文件上传，不直接回显；Webhook 地址在列表中展示但审查报告不记录实际值。
- 权限与版本：`saasVersion`、站点角色、插件开关、超管身份共同控制菜单显隐。

## 10. 复刻实施顺序建议（供下一步设计讨论）

1. 阶段 0：登录 + 全局壳（侧栏/顶栏/主题/路由骨架）。
2. 阶段 1：数据总览 + 上线流程。
3. 阶段 2：用户、审核、站点、订单、接单员（核心业务闭环）。
4. 阶段 3：营销、库存、商家、私信、广告、提现。
5. 阶段 4：小程序、服务号、素材、通知、通用设置、管理员。
6. 阶段 5：授权类页面与超管专属页。

每个阶段以“可运行、可点击、有完整状态反馈”为完成标准，不出现死链或纯占位页面。
