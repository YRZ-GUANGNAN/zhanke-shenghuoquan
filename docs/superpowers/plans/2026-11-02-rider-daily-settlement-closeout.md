# 骑手次日结算收尾与上线前验收计划

> 本文承接用户已确认的「00:00 + 收益账户」。记录真实代码和验收边界，不表示已经部署或发生微信打款。

**Goal:** 将骑手配送预计收入按北京时间次日 00:00 转入平台余额，保证历史余额不被重复入账、并发不多记账、未到期收入不能提前结款。

**Architecture:** 送达事务仅创建 pending 收入及零余额钱包；内部 worker 校验真实资金来源后，在同一事务中更新钱包、流水、earning 与通知事件。商家收益账户与配送充值账户分开，但收益来源尚未选定，本次不新增商家收益写接口。

**Tech Stack:** Go、GORM、MySQL 8.4、Taro、TypeScript；无新增依赖。

## 一、已确认规则与范围

- 业务时区为 Asia/Shanghai。以订单原始 `DeliveredAt` 确定收入归属日及下一次午夜，不使用网络重试时间。
- 今日预计收入与预计待结算收入可见；pending 不进入可用余额，不能后台提前结款、进入自动结款占用流程。
- `settled` 表示已计入平台内部余额，不代表微信或外部账户到账。
- 提现继续采用后台人工处理方向；不接通微信自动转账。本轮没有开放真实提现写入口，现有 `withdrawalWritesReady=false` 仍保留。
- 商家现有配送充值功能不变。商品应收不是配送费，更不是 `PlatformCutCents`；不能凭配送抽成生成商家收益。
- 保留现有 UI 风格、路由、身份守卫和既有通知权限，不推送、不上传、不部署、不执行线上资金写入。

- [x] `rider_daily_settlement_repository.go`：钱包 → earning 锁顺序；幂等键沿用订单 public ID；重放流水使用当前读，修复 REPEATABLE READ 并发快照导致的找不到流水。

- [x] 前端钱包 DTO/规范化/页面测试：三种结算状态、北京时间、未知字段、非法金额及时间。
