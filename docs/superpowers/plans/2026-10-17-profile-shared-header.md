# 用户主页：共享头部与内容横滑

用户已明确要求：封面底部没有细线，帖子与二手横滑时不带动背景、头像和资料。保持原色调、路由、接口、关注、私信、举报和返回手势。

## 决定

当前 `ChannelPager` 的每一页都复制 hero 和 tabs，是整个主页一起横移的直接原因。改成一个共享纵向 `ScrollView`，hero 与 tabs 各渲染一次，只有内容列表放入横向分页器。标签仍吸顶；封面可见时保留当前纵向偏移，头部收起后恢复各栏阅读位置，切换不重复请求。分页器按实际列表测量高度，给短列表保留视口所需空间，切换后的高度提交后再恢复阅读位置，避免从短列表切回长列表时滚动偏移被夹紧。横滑仍由原生 Swiper 完成，滑后防误触和边缘返回不变。

共用封面渐变在底部提前达到不透明白色，并延伸一个物理像素覆盖边界采样。两个主页允许渐变覆盖图片的分数像素边缘，编辑器仍保留圆角裁切；图片设为块元素。不改变照片裁切比例或额外模糊。

## 实施与验证

- [x] `user-profile/index.tsx`：单一共享 hero/tabs/纵向滚动容器，只分页列表；测量两栏自然高度并在内容/机型变化时更新。
- [x] `user-profile/index.scss`：共享滚动、吸顶标签和内容分页高度；共用 `profile-cover-surface.scss` 修正边界渐变。
- [x] 扩展既有主页行为检查，验证 hero/tab 唯一且在 Swiper 外，左右切换保留共享滚动、分页去重及失败归属，按钮/边缘返回可用。
- [x] 微信开发者工具验证浅色与深色封面边缘，两个频道横滑前后截图与实际事件；正常构建和演示构建均通过，已上传演示开发版本。

验收记录：390×844 视口中封面、资料、标签切栏前后的 left/top 完全一致；原生纵向容器在 40px 处切栏仍为 40px，收起头部后从帖子 250px 切到短商品栏约 247.67px，再切回帖子准确恢复 250px。普通构建 30 页且无演示素材；演示构建 9 页。真实手机手势手感留待扫码验收，不将开发者工具事件测试当作双真机验收。

自审：固定的是横向归属，不把高大的头部永久固定在屏幕上；纵向浏览仍可收起头部并吸顶栏目。无新增业务功能，无生产数据写入。
