# 刷新生命周期与商家状态恢复

基线：`94af9dc`，微信已上传源码为 `5af43e8` / `2026.10.17.6`。后续修改独立保存在 `codex/workbench-refresh-recovery-20261017`，不覆盖已上传包。

## 依据与设计决定

- 帖子资料库远端仍为 `ffbefc4`。实际阅读静态手势、动效研究和模拟器第八轮结果，采用“中断作废旧回调、状态不依赖动画完成、返回后恢复操作”的原则，不把 Android 静态参数当作小程序实测。
- 蜂鸟资料库更新为 `450b427`。阅读 `docs/状态与页面区块研究.md` 和 `data/state-layout-matrix.json`：错误、无数据、权限受限分别表达；订单非空时局部读取失败保留内容；各区块独立处理状态。研究仓库的未提交资料保持原样，只使用已提交证据。
- 闲鱼本地基础交互资料未发现新版本；图集和返回规则沿用现有实现，不加入未验证的交易行为。
- 保持当前色调、布局和原有服务契约。资格检查仍先于商家订单与钱包读取，核验未通过不显示可操作订单；仅临时核验错误提供原地重试，审核中/未通过继续使用现有返回入口。
- 下拉刷新继续由原生 ScrollView 处理阻尼与方向。增加隐藏、卸载和更换账号后的事件边界，结果反馈仍依据真实请求成功/失败。
- 商家分页使用同步请求锁，防止同一帧多次触底重复读取；刷新或更换账号使旧分页失效，旧请求不能解锁新分页。

## 实施与验证

1. 扩展现有真实组件隔离回归，先复现隐藏后的 pulling、卸载后的旧刷新事件、商家资格临时错误无重试和同帧分页重入。
2. 最小修改共享刷新组件及商家工作台，复用现有状态图形与按钮样式；不新增服务、依赖、图片或业务数据。
3. 回归失败重试、重复点击、请求中切换账号、旧响应与权限撤回；保留原有商家/骑手履约测试。
4. 执行相关专项、miniapp 类型检查与正式构建；检查生产配置、后端、咨询页和原项目未变化。真机触感另行标记待验。
5. 更新审查记录并本地提交。此次后续修复不再次上传微信，不部署管理网站、服务端或数据库。
