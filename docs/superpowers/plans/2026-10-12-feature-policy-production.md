# 小程序模块配置中心正式化实施计划

> 沿用用户已确认的功能显隐设计，并按“zhandui.top 可以随时关闭模块”的要求正式化。在当前隔离工作区直接执行，不启动额外代理、不覆盖原项目、不改变审核账号的行为。

**Goal:** 管理员在真实后台保存模块策略，小程序通过真实 API 更新入口、路由和请求约束。

**Architecture:** MySQL 单行策略、版本锁和事务审计是唯一配置来源。后端定期刷新并在新请求检查；小程序共享快照、前台刷新、轮询和页面门控。基础账号与已开始订单的履约能力保留。

**Tech Stack:** Go/Gin/GORM/MySQL、React、Taro/TypeScript。

## 设计决定

- 正式配置默认启用，不再依赖 LAB 构建变量；首次初始化保留已有模块，仅社区发言默认为管理员。
- 已知 key 的读取失败采用关闭可选模块的结果；保存只接受完整白名单和准确版本。普通管理员只读、active 超级管理员写入，沿用会话和 CSRF。
- 现有 13 项增加搜索、点赞、收藏、互动通知、身份申请、统一发布、商品留言，覆盖全部现有可选业务入口；具体校园工具仍通过已有导航分类/入口启用状态管理。
- 父项关闭只限制有效能力，不改子项的保存值。全关后首页保留状态说明、“我的”和账号、隐私、反馈等必要入口。
- 后端缓存最长 2 秒，小程序前台轮询 15 秒、回前台立即更新、写入前强制更新。无法声称离线设备即时收起；后端拒绝其新业务请求。
- 订单查询、付款/退款、钱包、已接订单的履约和订单参与方沟通不属于可选关闭项。工作台关闭后仅保留这些必要历史操作。
- 新管理域名独立静态目录，小程序 API 仍使用 zhanduiwang.top；DNS 不一致时阻止迁移。
