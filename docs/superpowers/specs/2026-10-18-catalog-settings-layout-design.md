# 商品设置与布局设计

日期：2026-10-18

## 依据与边界

本轮以 G-② Catalog、G-⑥a Admin、G-⑥a-2 Review、ADR-001 和外卖目录设计文档为约束。文档明确了商品字段、金额单位、媒体引用、分类、排序、审核和上下架状态机，也明确了后台列表筛选、详情侧栏、CAS 写入和学生端只读展示；文档没有规定具体视觉稿、图片比例、字号或颜色，因此以下是基于真实字段的视觉落地，不宣称为文档原样布局。

不新增接口、字段、状态或业务流程，不改变审核、媒体、支付、订单和身份守卫。所有图片继续使用已审核媒体；没有图片时显示中性无图态。金额始终来自 `priceCents`，界面只负责格式化。

## 页面落地

### 商家端

- 顶部改为连续白色工作区，商家名称、营业状态和当前位置形成稳定层级。
- “菜品 / 订单”作为主分段；菜品下先显示分类筛选，再显示“新增菜品”编辑区和商品列表。
- 编辑区按名称、描述、价格、排序、分类、图片顺序组织；图片使用固定媒体框，保存与状态操作分离，保留原 CAS 参数。
- 商品列表采用统一行高：图片、名称/描述、分类、价格、状态和操作各自有明确位置；操作只显示当前状态允许的动作。
- 分类和状态筛选使用轻量文字标签，不依赖大面积渐变或装饰卡片。

### 学生端

- 商家信息与商品列表分开，商品使用规则双列媒体网格；图片固定比例、标题两行截断、价格优先展示。
- 只渲染接口返回的商品及 `on_shelf` 状态，不补评分、销量、距离、优惠等文档未定义字段。
- 无图商品保留同尺寸中性媒体框，避免布局跳动；加载、错误和空态沿用现有状态组件。

### 管理后台

- 菜品列表继续使用文档规定的筛选、分页和详情侧栏，新增字段信息层级：名称/描述、分类、价格、媒体引用、状态和排序。
- 详情侧栏使用事实网格，不引入不可写的假编辑控件；状态写操作继续由现有服务端 CAS 接口负责。
- 桌面端保持表格密度，小屏端允许横向滚动；触控和键盘焦点不改变现有管理契约。

## 视觉与响应式规则

- 8pt 节奏映射到现有 `rpx`/`px` 令牌，白色内容画布、细分隔线和低对比状态色为主。
- 媒体只使用圆角和 `aspectFill`，文字区域不做无意义大卡片；价格使用等宽数字和明确的人民币符号。
- 小于 360px 的设备降为单列编辑字段，商品卡仍保持规则双列并缩小媒体间距；不产生横向溢出。
- 所有主操作保持至少 44px 触控尺寸；`prefers-reduced-motion` 下不增加动画负担。

## 验证

- MiniApp/Admin TypeScript 检查、现有业务契约检查、`npm run verify` 和生产构建。
- 重点检查字段映射、金额格式、状态动作、无图态、窄屏横向溢出和未修改的接口路径。
