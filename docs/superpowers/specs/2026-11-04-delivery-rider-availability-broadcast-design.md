# 配送骑手主动接单与新单广播设计

状态：已获用户确认，待实施计划与代码实现。范围仅为当前 `delivery` 配送域；不复用旧 `takeout` 外卖域的骑手接单状态、容量统计或商家页面。

## 目标与边界

- 真实配送订单进入 `ready_for_claim` 后，通知给主动开始接单且未达到同时配送上限的骑手。
- 本轮不区分校区/区域，统一视为全校园配送池；保留字段扩展点，但不根据自由文本地址猜区域。
- 同时接单上限由后台配置，默认值必须是明确的安全值并可通过并发测试；管理员修改使用行版本和正整数校验。
- 骑手必须主动执行“开始接单”；停止接单、账号失效、达到容量、订单被抢/取消/过期后，不再接收或发送该订单通知。
- 通知资格解析和抢单事务共享同一资格规则；通知发送前再次查询当前订单和骑手状态。通知失败不改变订单事实。
- 保留现有订单路由、支付、钱包、日结、私信和工作台布局；不添加假数据，不改变已部署版本，默认关闭新开关。

## 数据与接口

新增配送域骑手工作状态表，按骑手唯一用户关联，至少包含：`rider_user_id`、`state`（`off_duty`/`on_duty`）、`scope`（本轮固定 `campus`）、`max_in_flight`、`row_version`、更新时间。状态变更必须使用当前行版本，账号关闭/资格撤销时强制回到 `off_duty`。

新增全局配送容量配置（或等价的现有配送配置扩展），至少包含：配置范围、`max_in_flight_per_rider`、行版本和更新时间。取值为正整数，设置上限防止溢出和意外无限接单；读取失败、缺少配置或配置关闭时保持广播关闭。

新增骑手“开始接单/停止接单”鉴权接口，响应当前状态、容量上限和已占用数量；前端只显示服务端事实。开始接单不能绕过身份、账号状态或骑手资格检查，停止接单不取消已有配送。

候选资格函数必须同时检查：账号 active、骑手资格可用、工作状态 `on_duty`、scope 为 `campus`、当前未完成配送数量小于上限、订单仍为 `ready_for_claim`、订单版本未变化、用户订单通知偏好未关闭。容量统计只针对当前 `delivery_orders` 的 `claimed`、`to_pickup`、`picked_up`、`delivering` 状态，不读取 `takeout_fulfillments`。

## 事件与并发

现有 `RiderPoolOpened` 事件继续在支付确认进入 `ready_for_claim` 的同一订单事务中写入，事件 TTL 保持 10 分钟。展开器解析候选骑手时使用资格函数；没有候选时记录可观测的跳过原因，而不是伪造成功。发送前 guard 再次验证事件未过期、订单版本和状态未变、骑手仍在岗且未满载。

抢单事务必须在同一数据库事务中锁定订单并重验当前 rider availability 与 in-flight 数，再执行唯一状态转换；达到容量、停止接单或订单已被其他骑手抢走时返回明确业务错误。通知到达不保证抢单成功，客户端必须重新查询订单。

同一骑手的开始/停止接单、抢单、完成配送和后台容量修改必须使用稳定锁序：先锁骑手工作状态/容量配置，再锁订单或按订单唯一 ID 升序读取计数；实现前核对退款、支付、日结锁图，避免跨域反向等待。所有计数和状态更新使用行版本/CAS，金额与订单状态不在通知 worker 内修改。

## 错误与兼容

- 新表、配置或资格查询不可用：广播及抢单入口 fail-closed，现有已分配订单仍可按原流程配送。
- 通知发送失败只重试通知任务，不重复创建订单事件；订单被抢、取消或过期的未发送任务标记 `skipped`。
- 旧 `takeout` 骑手状态和 `MaxInFlightPerRider` 不参与当前配送域资格；不得通过旧 active 状态直接广播。
- 新接口缺失、字段未知或服务端错误时，前端保持不可接单，不用本地缓存伪造“已开始接单”。

## 验收

1. 默认关闭、未开始接单、资格撤销、容量已满、订单非 `ready_for_claim` 均不产生骑手广播。
2. 开始接单后可收到符合条件的新单；停止接单、达到上限、订单被抢/取消/过期会阻止后续发送。
3. 通知与抢单并发下最多一个骑手成功；同一骑手不能超过容量；重复事件只生成一组任务。
4. 配置行版本冲突、缺表、查询超时、通知失败和回调重放均 fail-closed，不改订单/钱包事实。
5. 隔离 MySQL 并发测试覆盖开始/停止、容量边界、抢单竞争和事件幂等；现有全量 verify、Go test、typecheck、构建和 diff 检查继续通过。
6. 真机验收只使用用户主动开始接单的测试骑手；推送受限于已授权白名单，不向普通用户群发。

本设计不包含微信订阅消息密钥配置、真实支付、次日结算或自动提现；这些仍按各自的真实账号和财务验收门槛单独执行。
