# 商家工作台局部精修设计

## 目标

在不改变商家身份审核、真实订单、钱包开关、发布配送单、订单详情和消息链路的前提下，把商家首页从“多个同权重盒子的集合”收敛为“订单优先的轻量经营台”。

## 当前问题

- 商家资料、统计、快捷功能、状态标签和订单卡片的视觉权重接近，首屏主次不够明确。
- 商家地址前绿色圆点只是静态装饰，却容易被理解为在线状态。
- 钱包、单量、配送中三个指标的排版不统一，“未开通”比数字更抢眼。
- 四个快捷入口的图标底色不一致，发布入口的蓝色实心块显得突兀。
- 状态标签的零数量仍使用徽标，弱信息占据过多注意力。
- 订单头部把长订单号和时间挤在一行，状态、路线、备注和详情按钮的层级不够稳定。

## 设计原则

1. **订单优先**：压缩资料、指标和快捷功能的纵向空间，让真实订单更早进入首屏。
2. **连续白色画布**：维持现有页面结构，减少卡片边框和阴影的竞争，不引入装饰性背景、渐变或虚构图片。
3. **真实状态**：钱包关闭时继续显示“未开通”，订单数量、状态、地址、联系人和费用仍完全来自现有接口。
4. **统一节奏**：使用现有设计令牌、8rpx 节奏、弱分隔线和一致的圆角体系。
5. **可触达**：身份切换、状态标签和详情按钮保持不低于 44PX 的有效点击区域。

## 页面结构

### 商家资料区

- 保留头像、商家名称、“已审核”徽标、商家地址和“切换身份”。
- 删除地址前绿色圆点；地址只表达资料内容，不表达在线状态。
- 长商家名单行省略，地址最多两行；切换按钮为浅蓝弱操作，避免与订单详情主按钮竞争。

### 经营指标

- 保留三列：钱包余额、累计单量、配送中。
- 三列统一居中、统一数值基线，整体高度压缩到约 104rpx。
- “未开通”使用中性状态文字，不伪造 `¥0`。

### 常用功能

- 保留 2×2 网格与现有四个入口及路由。
- 图标容器统一为 56rpx；发布入口只保留克制的主色强调，其余使用同一浅色底。
- 卡片降低高度、减少阴影，标题和说明保持单行省略。

### 订单状态标签

- 保留待接单、配送中、已完成三列与真实 `total`。
- 标签提供至少 44PX 的触控高度；零数量显示为普通灰色数字，非零数量才使用轻量徽标。
- 活动下划线缩短，避免视觉过重。

### 订单卡片

- 订单头部拆成“配送单 / 完整订单号 / 创建时间”三层，并在右侧保留真实状态。
- 完整订单号在窄屏省略显示，但详情路由仍使用未截断的 `deliveryOrderPublicId`。
- 取货点和送达点使用两个独立路线节点，连接线随内容高度增长，避免长地址导致圆点错位。
- 取送地址提高字号与对比度，联系人作为次级信息。
- 备注改成轻背景信息行；配送费和详情按钮对齐到同一底部基线。
- 有骑手时继续显示真实骑手信息和消息入口；无骑手时不增加假状态。

## 业务边界

- 不修改 `useIdentityGuard('merchant')`、`getIdentityApplication('merchant')` 和身份切换流程。
- 不修改三组 `listMerchantDeliveryOrders` 请求、真实 `total`、触底分页和按 `deliveryOrderPublicId` 去重。
- 不修改 `deliveryPaymentEnabled`、`getDeliveryWallet()` 或“未开通”诚实状态。
- 不修改四个快捷入口路由、订单详情路由和 `role=merchant` 会话路由。
- 不新增固定余额、固定单量、模拟商家、模拟订单或装饰图片。

## 响应式边界

- 320–430px 宽度保持三列指标、两列快捷入口和三列状态标签。
- 商家名与订单号单行省略；地址最多两行；路线地址允许自然换行。
- 切换身份、状态标签、详情按钮使用固定 44PX 最小触控高度。
- 计数使用紧凑显示函数，超过 99 显示 `99+`；经营指标超过 9999 使用“万”单位，避免六位数撑列。
- 订单卡底部在窄屏仍保持费用与详情按钮同排，金额单行省略。
- 列表底部继续包含 `env(safe-area-inset-bottom)`。

## 验收标准

- 页面首屏比当前版本更早露出订单标签或订单内容。
- 商家地址前不再出现绿色圆点。
- 四个快捷入口视觉语言一致，发布入口仍可被识别为主要入口。
- 长文本不会挤压身份切换、状态徽标、路线节点或详情按钮。
- 所有现有真实接口、路由、审核门槛和分页行为保持不变。
- 商家工作台契约、角色工作台契约、业务闭环、胶囊布局、类型检查、构建和完整验证通过。
