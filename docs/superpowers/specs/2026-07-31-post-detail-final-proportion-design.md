# 帖子详情最终比例收口设计

## 目标

在保留真实帖子、关注、评论、点赞、收藏与微信胶囊独占行规则的前提下，修正帖子详情页在 Android 与 iPhone 真机上的视觉比例。重点消除“作者信息太弱、关注按钮太重、标题过大、无评论区域空洞、底部动作松散”的问题。

## 设计判断

1. 不修改全局胶囊安全区计算。当前安全区按 `statusBarHeight` 与微信胶囊底部计算，能避免按钮与官方胶囊重叠；截图中的上方空间属于系统行，不是重复占位。
2. 帖子详情业务行采用紧凑的 48px 逻辑高度：作者头像 32px，昵称 14px，学校信息 11px；关注按钮视觉尺寸 58×32px，同时由外层维持 44px 可点击热区。当前 Taro 构建会把源码 `px` 自动转换成 `rpx`，因此实现层统一按 `2rpx = 1 逻辑像素` 明确书写，避免真机尺寸被再次缩小。
3. 正文建立稳定的移动端字号梯度：标题 36rpx、正文 29rpx、标签 23rpx、元信息 22rpx。无图片帖子顶部留白收敛到 24rpx。
4. 评论区不再用一行“暂无评论”制造空洞。无评论时显示紧凑空态卡，包含明确标题与引导文案；有评论时保持真实列表。
5. 底部操作栏高度、输入框和三项统计使用一致的 44px 点击目标；图标与数字纵向排列，避免横向挤压输入区域。
6. “我的内容”列表维持原有四个业务标签，但进一步压缩卡片、缩略图和状态胶囊，保证首屏能稳定展示更多真实内容。

## 功能边界

- 不修改后端接口、审核策略、真实数据来源或统计逻辑。
- 不引入假图片、假帖子、假评论或装饰性媒体。
- 不恢复已放弃的全局 UI 实验。
- 不上传微信版本；仅交付通过构建、回归检查并可由用户直接上传的代码。

## 验收标准

- 官方胶囊与业务按钮不重叠。
- 关注按钮不再成为标题区视觉主体，且仍具备不小于 44px 的点击热区。
- 无图帖子首屏能同时看到作者、标题、正文、标签、时间及评论标题。
- 无评论区域高度受控，不出现大面积无意义留白。
- 底部输入框和三项动作在 320px、375px、430px 宽度下不换行、不溢出。
- `typecheck`、微信小程序构建、胶囊布局检查、静态路由检查、业务闭环检查和回归契约全部通过。
