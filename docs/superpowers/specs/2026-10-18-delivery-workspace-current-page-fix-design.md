# 商家与骑手当前工作台修复设计

## 范围

本次只修商家端和骑手端当前工作台页面，不改变学生端、社区、二手、发布、支付、身份守卫或已有订单接口。现有底部入口继续保留：商家为“订单 / 发单 / 消息 / 我的”，骑手为“接单 / 配送 / 消息 / 我的”。

本次不新增淘宝、京东、美团的直连能力。外部订单继续通过已经存在的回调收集接口进入服务端，工作台只消费已有配送订单数据；没有授权的第三方回调或密钥时不伪造订单。

## 目标行为

1. 商家首页和骑手首页的手势区域覆盖整个工作台页面，而不是只覆盖顶部 hero。左右滑动沿用学生端的方向判定和点击抑制规则：水平位移至少 64px、横向位移显著大于纵向位移时才切页；垂直滚动、表单输入、订单卡片操作和下拉刷新不触发工作台切换。
2. 手势切换与底部导航使用同一份可见入口列表。商家滑动顺序为“订单 → 发单 → 消息 → 我的”，骑手为“接单 → 配送 → 消息 → 我的”。处于列表边界时保持当前页面，不循环、不误跳转。
3. 封面只作为角色工作台的顶部媒体层：有真实封面时使用 `aspectFill` 覆盖顶部区域，资料内容自然叠在封面底部；无封面或加载失败时使用中性无图背景。封面底部不额外绘制黑线、白色圆底或装饰图。
4. 头像使用现有 `ChatAvatar` 与真实头像字段。头像边界只保留一次，保证在封面和无封面两种状态下都能读清姓名、角色和审核状态。
5. 顶部系统胶囊、角色资料、当前工作区标题和订单内容保持稳定的垂直节奏。封面不挤压订单滚动容器，底部导航包含安全区并固定在页面底部。

## 交互方案

`useDeliveryWorkspaceNavigation` 继续维护角色入口、权限过滤、路由目标和防重复锁。将它返回的手势 handlers 绑定到工作台根容器，并让页面根容器只在当前工作台可见、没有确认弹窗和提交锁时接收手势。导航项过滤后的顺序作为手势索引来源，避免隐藏入口造成跳页错位。

保留 `ChannelPager` 对商家订单分组和骑手履约阶段的内部滑动。工作台级别的左右手势只负责切换四个底部入口；订单分组、配送阶段和页面级切换不能共享同一个索引或事件锁。点击事件在原生滑动结束后的短时间内继续被抑制，避免滑动松手误打开订单或跳转页面。

## 封面布局

角色首页与“我的”页面采用同一套封面变量：顶部媒体层固定高度，系统胶囊位于媒体层之上；头像与资料块通过负边距自然接入，正文背景从资料块之后连续展开。`Image` 只负责真实 `profile.cover`，错误时清除媒体层状态，不替换成生成图片。样式使用 `overflow: hidden`、明确的 z-index 层级和同一方向的渐变遮罩，禁止对图片容器再套一层白色圆形底。

## 外部订单边界

服务端已有外部订单收集端点负责签名、幂等和平台来源记录。商家工作台继续读取 `listMerchantDeliveryOrders` 返回的真实订单，按来源平台和取货号显示。若没有平台授权或回调不可用，界面显示“未接入/暂无订单”状态，并提供原有重试入口；不在小程序内抓取第三方页面，也不在前端生成订单。

## 验证

- 运行 `npm --workspace apps/miniapp run typecheck`。
- 运行 `node scripts/check-role-workbench-ui.cjs` 和 `node scripts/check-channel-pager.cjs`。
- 运行 `npm run build:miniapp`。
- 以 320、390、430 宽度检查商家与骑手页面：有封面、无封面、封面加载失败、长姓名、长地址、订单为空和订单加载失败。
- 手势验收：根页面左右滑动可到消息和我的；垂直滚动不切页；订单卡片按钮点击不被拦截；边界滑动不循环；底部导航点击和手势最终状态一致。

## 自审结论

本设计只修当前角色工作台的布局承载和导航手势，不引入新的业务数据或第三方接入。所有图片都来自现有真实字段，现有订单、权限、支付和外部回调契约保持不变。
