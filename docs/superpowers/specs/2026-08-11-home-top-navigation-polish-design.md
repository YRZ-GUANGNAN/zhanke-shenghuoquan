# 首页顶部导航细节优化设计

## 目标

在不改变“私信 / 发现 / 工具 / 搜索”业务入口、不压缩微信官方胶囊安全区的前提下，改善首页顶部业务导航行的对齐、触控面积、选中反馈与小屏适配。

## 现状判断

- `CapsulePageHeader` 已将微信胶囊系统行与业务导航行分离，当前顶部留白属于安全区，不应通过负边距或固定高度覆盖。
- 三个标签依赖大间距排列，标签自身横向触控面积偏小；在 360px 临界宽度又会突然切换间距，容易产生跳版。
- 搜索入口虽然占有 44px 方形区域，但图形由 CSS 伪元素拼接，尺寸偏小、缺少语义和按压反馈。
- 当前选中下划线略厚，且未选与选中文字字重不同，切换时存在轻微视觉抖动。

## 方案

### 导航结构

- 保留 `CapsulePageHeader variant="tabs"` 及共享胶囊几何，不修改 `capsule-safe` 和 `capsule-layout`。
- 业务行维持左侧三项导航、右侧搜索入口。
- 三项导航组成最大宽度 `432rpx` 的等宽轨道，每项以 `flex: 1` 分配空间；单项最小宽高均为 44px。
- 移除针对 360px 的突变式间距规则，由 Flex 在 320–430px 屏宽连续适配。

### 视觉与交互

- 标签字号保持 `32rpx`，所有状态统一 `font-weight: 600`，仅通过文字颜色和短底标表达选中状态。
- 选中底标调整为 `32rpx × 4rpx`，保持清晰但不过度抢眼。
- 搜索入口使用已有 `AppIcon name="search"`，图标大小约 20px；增加圆角按压底色和轻微缩放反馈。
- 标签与搜索入口增加 `role="button"`、可读的 `aria-label`，并用 `aria-current` 表示当前标签。

## 功能边界

- 标签切换仍只调用现有 `setActiveTab`；搜索仍调用现有 `openSearch`。
- 不新增路由、接口、数据、图标依赖或动画库。
- 不改变私信、发现、工具内容区，也不上传微信版本。

## 验证

- 更新胶囊布局契约，检查等宽导航、44px 触控热区、语义属性、项目搜索图标及按压态。
- 运行 `check:miniapp-capsule-layout`、`check:home-real-tools-contract`、`check:home-feed-card-contract`、小程序 TypeScript 检查和本地构建。
- 最终由用户在微信开发者工具和 Android/iOS 真机审查视觉密度与触控表现。
