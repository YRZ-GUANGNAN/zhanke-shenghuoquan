# 湛科生活圈发布候选收敛设计

日期：2026-07-31

## 目标

把当前 `master` 上已经完成但尚未全部提交的业务改动收敛为一份可构建、可验证、可回退的发布候选版本。范围覆盖微信小程序、Go 后端与 React 管理后台，但不新增支付能力、不上传微信版本、不修改生产数据，也不再发起大范围视觉重设计。

## 已选方案

采用“发布候选收敛”，不采用以下两种方向：

1. **全量重写或统一换肤**：视觉变化大，但会重新引入此前已经回退的信息流方向，并扩大业务回归面。
2. **立即冻结并直接上传**：风险最低，但会保留架构检查误报和 CSS 顺序警告，无法形成稳定的交付基线。
3. **发布候选收敛（采用）**：保留现有业务与真实数据合同，只修复已证实的缺口，按独立提交完成业务、架构、构建和验收收尾。

用户已明确把本轮安排权交由 Codex，并要求不再逐项确认；因此本设计在不扩大业务范围、不上传版本、不改生产数据的边界内视为已批准。

## 范围

### 1. 保全现有成果

- 保留当前工作区内的二手留言、一级回复、自动审核、人工改判、通知定位、星标收藏、腾讯云 IM 与发布链路改动。
- 不使用 `git add .`，不重置用户文件；按功能域精确暂存和提交。
- `.env`、密钥、生产数据库和微信后台均不在自动修改范围。

### 2. 业务闭环

- 商品留言与回复必须使用服务端真实用户、商品和审核状态。
- 自动审核只处理帖子、商品与商品留言；身份申请继续人工审核。
- 自动审核不确定、超时、未配置或异常时必须保持待人工审核，不能默认公开。
- 管理后台必须能识别自动审核来源、查看原因并进行有理由的人工改判。
- 已售商品保留历史留言读取，但禁止新增留言、收藏和新会话。

### 3. 发布确定性

- 更新架构边界检查，使 `adminauth` 与 `identityapplication` 成为已分类模块。
- 身份申请中的跨媒体事务只能由明确列出的事务编排文件持有 `*gorm.DB`；边界检查不得变成任意白名单。
- 统一同时引用 `StudentBottomNav` 与 `CapsulePageHeader` 的导入顺序，消除 CSS 抽取顺序警告。
- 保留 `vendors.js` 体积警告为非阻断项；当前不做高风险拆包。

### 4. 体验收敛

- 不改变已经确认的蓝白视觉体系与业务导航结构。
- 小程序继续为微信胶囊单独让出系统行；底部操作区兼容 iOS 安全区和键盘。
- 管理后台保持当前导航和功能，只补足加载、空、错误、处理中和审核反馈状态。
- 不制造图片、评分、广告、促销、用户或商家数据。

### 5. 验证与交付

- 前端合同检查、TypeScript、管理后台生产构建和小程序生产构建必须通过。
- 后端聚焦单元测试必须通过；共享 MySQL 的破坏性或环境型集成测试与源码回归分开记录。
- 构建产物保留在 `apps/miniapp/dist` 和 `apps/admin/dist`。
- 最终只提供上传版本号、说明与操作步骤，由用户在微信开发者工具中上传。

## 数据与错误处理

- 所有写入沿用现有 `clientRequestId`、`Idempotency-Key` 与 Outbox 合同。
- API 请求失败时保留当前内容并显示可重试状态，不回退到本地假数据。
- 管理后台审核动作在服务器返回成功后刷新；失败时保留选中任务和错误信息。
- 微信内容安全审核失败关闭：无法确定结果时转人工，不自动通过。

## 验收标准

1. 所有现有聚焦检查和前后端类型检查通过。
2. 管理后台与小程序生产构建通过，CSS 顺序警告消失。
3. `check:boundaries` 通过，且只允许明确的身份申请事务编排文件直接接触 GORM 事务。
4. 二手留言、自动审核、后台改判相关 Go 测试与前端合同检查通过。
5. `git diff --check` 通过，不提交密钥与本地缓存。
6. 不执行微信上传、不更改体验版、不写生产数据库。

## 非目标

- 微信支付、配送钱包真实结算和企业微信 Webhook 的新配置。
- 对所有历史页面进行重新设计。
- 为共享测试库清空数据或强行运行破坏性迁移回滚。
- 将构建成功宣称为双账号、双真机的全部业务验收。
