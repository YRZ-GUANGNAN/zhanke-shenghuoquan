# 学生端外卖、资料头部与头像闭环设计

## 目标

在不改变现有业务路由和真实数据合同的前提下，精修学生端外卖页与“我的”资料头部，并把头像选择、审核、资料保存和重新加载串成可验证的真实闭环。

## 设计原则

- 外卖目录只展示 `external_takeout_merchants` 返回的真实合作商家；无数据时保留诚实空状态，不生成商家、评分、图片或促销信息。
- 资料头部强调“头像、昵称、身份、校园信息”四级信息，不使用装饰性大渐变或无业务含义的图形。
- 头像只能通过现有受控媒体管线以 `purpose=avatar` 上传，审核通过后再关联用户资料。
- 页面内的临时预览只用于上传过程；保存成功后必须使用后端返回或重新读取的正式头像 URL。
- 保留现有身份切换、我的内容、设置等入口，不改权限和业务行为。

## 外卖页

### 首屏层级

- 标题“外卖”和搜索入口保持同一业务行，搜索入口扩大为更稳定的胶囊区域。
- 目录说明调整为主说明“校外合作商家”和动态状态说明，减少两段文字争抢视觉焦点。
- 真实商家存在时展示营业筛选；无商家时不展示无意义筛选。

### 提示与空状态

- 跳转第三方小程序的责任提示改为轻量信息条，不作为黄色告警大面积占位。
- 空状态使用简洁的目录图形、标题和说明，不使用虚假图片。
- 加载失败状态保留可点击重试，和正常空状态明确区分。

## “我的”资料头部

- 头像增大并使用圆形裁切；有真实头像时 `aspectFill` 展示，没有头像时显示昵称首字兜底。
- 昵称与身份标签同排，用户号和学校/校区分两行，避免当前文本拥挤。
- 编辑入口改为轻量文本按钮，确保不与微信胶囊冲突。
- 点击整个资料区域仍进入编辑资料页，保留原行为。

## 头像真实闭环

1. 用户在编辑资料页选择相册或相机图片。
2. 客户端压缩图片并调用 `/api/v1/miniapp/media/uploads`，用途为 `avatar`。
3. 客户端完成 COS 直传并轮询媒体审核，只有 `approved && canUse` 才允许作为待保存头像。
4. 保存资料时调用 `PATCH /api/v1/auth/me`，携带 `avatarAssetId`。
5. 后端通过媒体预留、用户资料更新、媒体引用提交三步完成关联；任一步失败执行现有回滚。
6. 客户端使用后端返回值更新会话，并额外调用 `GET /api/v1/auth/me` 校验正式资料，保证头像 URL 可跨页面和下次登录回显。
7. 上传取消、审核拒绝、审核超时、保存失败均保留旧头像，并给出明确错误，不显示假成功。

## 验证范围

- 增加静态合同检查，覆盖头像媒体用途、审核等待、`avatarAssetId` 保存、服务端资料刷新和两个页面关键结构。
- 增加或补充后端头像更新测试，覆盖合法关联及失败不破坏旧资料。
- 运行 miniapp typecheck、相关合同检查、后端测试、完整 `npm run verify` 与生产构建。
- 不在本任务中上传微信版本；只生成新的、可回滚的候选包供最终审查。
