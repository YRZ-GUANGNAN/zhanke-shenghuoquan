# 静态假页面与失效入口收口设计

## 目标

让当前已注册的小程序页面只展示真实数据、真实能力或明确的空状态，不再出现静态业务夹具、固定热门词、无法执行的入口和误导性选项。

## 范围

- 审核 `app.config.ts` 已注册页面及其直接依赖。
- 删除未被业务使用的静态配送订单夹具。
- 热门标签只使用后端真实聚合结果；接口失败时展示空状态，不回退到伪造热词。
- 移除目前没有完整后端能力支撑的二手私信图片入口。
- 移除没有真实联系方式字段支撑的“微信联系”入口。
- 移除不会实际清理任何安全缓存的“清理缓存”入口。
- 新增静态契约检查，阻止上述问题回流。

## 不在本次范围

- 不重新注册历史遗留页面。
- 不伪造图片、用户、商品、帖子、订单、统计或联系方式。
- 不借用配送私信媒体权限实现二手私信图片。
- 不修改生产环境配置、数据库或微信后台，不上传版本。

## 交互原则

1. 有真实能力才展示操作入口。
2. 无数据使用诚实空状态，不填充演示数据。
3. 网络失败保留重试或错误提示，不回退到静态业务内容。
4. 未来恢复入口时，必须同时具备后端契约、权限校验、客户端实现和回归测试。

## 验收

- 已注册页面不引用静态配送夹具。
- 发帖页不包含固定热门标签回退。
- 二手聊天不展示失效图片按钮。
- 二手详情不展示永远无法使用的微信联系选项。
- 设置页不展示无实际作用的清理缓存行。
- 新增检查进入 `npm run verify`，全量验证与构建通过。
