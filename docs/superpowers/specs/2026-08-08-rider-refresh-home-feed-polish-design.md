# 骑手刷新与首页信息流精修设计

## 目标

在不改变现有业务接口、身份权限和页面路由的前提下，优化骑手工作台的订单刷新体验，并重整学生首页信息流卡片，使真实图片、无图帖子、二手商品和异常状态都以诚实、清晰且稳定的方式呈现。

## 设计边界

- 从 `master@fad5377` 创建独立 `codex/rider-refresh-home-feed` 分支；不修改或复用已放弃的 V5 UI 实验。
- 保留骑手身份校验、订单状态流转、抢单、取货、送达、释放、凭证和会话入口。
- 保留学生首页的私信、发现、工具、搜索、分页和详情路由。
- 不增加依赖，不复制淘宝闪购的品牌资产、图标或具体布局，只借鉴“下拉刷新”和高密度订单信息的交互原则。
- 不为无图内容生成或伪造媒体；真实图片加载失败时明确显示无图状态。

## 方案比较

### 方案 A：仅调整样式

保留手动刷新按钮与现有双列卡结构，只修改颜色、间距和圆角。改动风险最低，但无法解决刷新按钮挤压统计区、无图帖子被伪装成图片卡的问题。

### 方案 B：统一单列信息流

所有帖子和商品改为单列大卡。信息完整，但会显著降低真实图片内容的浏览效率，并偏离当前首页已经形成的双列发现心智。

### 方案 C：原生刷新 + 混合信息流（采用）

骑手页使用 `ScrollView` 原生 refresher；首页对真实媒体使用双列卡，对无媒体帖子使用全宽文字卡。该方案直接修复结构问题，同时保留既有业务和当前产品风格。

## 骑手工作台

### 刷新行为

- 开启 `refresherEnabled`，下拉时调用现有 `load()`，完成后关闭刷新状态。
- 初次进入仍显示加载状态；刷新失败时保留旧数据并展示轻量错误提示。
- 统计卡中的刷新按钮移除，改为“下拉刷新订单 · 最近更新时间”的状态行。
- 订单操作成功后仍使用现有 `refreshOrders()` 同步数据，不改变业务行为。

### 信息层级

- 顶部身份区保持姓名、认证状态和身份切换。
- 统计区突出“进行中”，次级展示“可抢”和“已完成”，避免按钮占据第三列。
- 标签栏保留待抢单、待取货、待送达，并继续显示真实数量。
- 空状态、错误状态和加载更多状态继续位于订单区域内，不用装饰性假订单填充。

## 首页信息流

### 内容模型

- `DiscoverCard` 增加明确的 `hasMedia`/`kind` 语义，不再用随机高度假装内容差异。
- 真实图片帖子和商品进入双列媒体网格，媒体比例固定为 4:5，减少跳动和裁切不一致。
- 无图帖子进入全宽文字流，显示频道、标题、作者和互动数。
- 无图二手商品保持诚实的“暂无图片”媒体面，因为交易卡仍需要稳定的商品浏览尺寸。

### 卡片层级

- 图片、标题、作者和互动数据使用统一间距与字号。
- 帖子和商品通过小型类型标签区分，不新增虚构评分、价格、活动或图片。
- 图片加载失败后切换为明确的无图状态，不继续保留彩色条纹占位。
- 加载、空、部分失败和重试状态改为全宽状态卡，避免看起来像业务内容。

## 可访问性与兼容性

- 可点击区域不小于现有尺寸；文字颜色沿用设计 token，保证浅色背景对比度。
- 保留 iOS/Android 安全区、微信胶囊让位和底部导航高度。
- 不依赖 CSS masonry 或新组件库，继续使用 Taro `ScrollView`、Flex 和现有图标组件。

## 验收标准

1. 骑手页可下拉刷新，刷新结束后恢复滚动状态，统计区不再出现独立刷新按钮。
2. 骑手订单加载、分页、操作、错误与空状态行为保持可用。
3. 首页真实图片卡比例统一；无图帖子不再显示伪造图片占位。
4. 私信、搜索、工具、帖子详情、二手详情和底部导航路由不变。
5. `typecheck`、miniapp 静态契约检查和 `build:weapp` 通过。
