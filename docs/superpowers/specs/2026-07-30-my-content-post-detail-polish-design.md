# “我的内容”与帖子详情页优化设计

日期：2026-07-30

## 目标

在不改变任何业务接口、审核流程和交互能力的前提下，修复“我的内容”列表样式失效以及帖子详情页无图内容留白过大的问题，使两个页面在 Android 与 iOS 真机上具备清晰、稳定的内容层级。

## 现状诊断

1. `my-content/index.tsx` 使用 `favorite-row`、`post-row`、`comment-row`、`item-row` 类名，`index.scss` 却仍使用旧的 `my-content-favorite`、`my-content-post`、`my-content-comment`、`my-content-market` 类名，导致卡片内部几乎没有命中样式。
2. “我的内容”外层把所有项目包在一个大卡片中，少量数据时像一块未完成的空白表单，标题、状态、价格和互动信息没有形成稳定层级。
3. 帖子详情媒体区使用固定大高度。图片地址失效或加载失败时仍保留整块媒体背景，造成截图中的大面积粉色空白。
4. 帖子详情的字体和间距偏大，作者、正文、标签、评论和底部操作栏之间缺少连续的阅读节奏。
5. 当前页面已经接入真实帖子、审核状态、关注、点赞、收藏和评论，优化必须保留这些行为，不能重新引入演示数据。

## 选定方案

采用“紧凑媒体列表 + 内容型详情页”，不采用大图卡片流或双列网格。

### “我的内容”

- 保留“收藏 / 帖子 / 评论 / 宝贝”四个标签及当前路由参数。
- 每条记录成为独立列表项，使用统一的媒体缩略图、正文区和尾部状态区。
- 帖子与收藏显示两行标题、作者或审核状态、点赞和评论数。
- 评论显示评论正文、来源帖子、时间和审核状态。
- 宝贝显示图片、标题、价格、商品状态和审核状态。
- 无图项目使用小面积的“无图”状态，不生成装饰图，也不占据大块版面。
- 加载、错误和空状态使用独立的状态面板；错误面板可点击重试。

### 帖子详情

- 胶囊系统区继续单独占行，业务标题栏保持固定并与胶囊互不重叠。
- 作者信息保留在标题栏，关注按钮仅在已审核公开帖子显示。
- 有有效图片时显示媒体区；图片加载失败后收起媒体区并显示正文，不留下占位大色块。
- 媒体区采用受限高度和 `aspectFill`，避免图片把正文推到首屏以下。
- 无图帖子直接从正文开始，正文区域不显示任何伪图片或彩色占位。
- 标题、正文、标签、时间形成连续内容块；评论区通过浅色分隔带与正文区分。
- 底部评论输入、点赞、星标收藏和评论数量保持现有行为，增加安全区适配与按压反馈。

## 数据与交互边界

- 不新增或修改后端接口。
- 不修改 `CommunityPost`、`CommunityComment`、`Product` 的业务字段。
- 保留公开帖子读取失败后尝试读取本人帖子、审核状态展示、viewer state、点赞、收藏、关注和评论提交流程。
- 保留“评论已提交审核”的提示。
- 不增加评论回复、删除、编辑或分享等未要求功能。
- 不改首页、个人主页、用户公开主页、商品详情或其他页面。

## 错误与降级

- 图片加载失败只影响图片本身，正文、评论和操作仍可用。
- 内容加载失败显示明确错误与重试入口。
- 评论单独加载失败时保留帖子正文，评论区提供重试。
- 空图片数组显示真实无图状态，不使用远程占位图或生成图片。

## 验证

1. `my-content` 四个标签的真实有图、无图、空列表、加载和失败状态。
2. 公开帖子、本人待审核帖子、有图帖子、无图帖子和坏图地址。
3. 点赞、星标收藏、关注和发表评论行为不回归。
4. iOS 与 Android 的胶囊安全区、滚动、底部输入栏和键盘弹出布局。
5. 小程序 typecheck、生产构建、胶囊布局检查、静态路由检查、业务闭环检查和 `git diff --check`。

## 非目标

- 不做全局视觉改版。
- 不恢复此前已经放弃的 V5 UI 实验。
- 不复制第三方社区产品的版式、图标或内容。
- 不修改生产环境、数据库或后台管理端。
