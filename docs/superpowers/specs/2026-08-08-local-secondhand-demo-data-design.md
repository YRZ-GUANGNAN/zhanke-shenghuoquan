# 本机二手商品演示数据设计

## 目标

在不修改线上数据、不向前端注入静态数组的前提下，为本机 MySQL 增加一组可重复写入、可完整清理的二手商品演示数据，用于检查当前二手市场的单卡、双列、标题换行、价格和分类布局。

## 范围

- 只连接 `backend/.env` 或显式 `MYSQL_DSN` 指向的本机数据库。
- 若数据库主机不是 `127.0.0.1`、`localhost` 或 `::1`，脚本必须拒绝执行。
- 不修改 miniapp 的接口地址、请求逻辑或审核逻辑。
- 不上传图片，不复用其他用户或线上商品的媒体资产；商品使用现有诚实无图状态。
- 不触碰现有商品、帖子、用户、审核任务和用户文档。

## 演示数据

写入 8 个 `selling + approved` 商品，标题统一带 `[本机预览]` 前缀，覆盖：

1. 数码：机械键盘，短标题，中等价格。
2. 数码：显示器支架，较长标题。
3. 书籍资料：高等数学教材与习题册组合。
4. 书籍资料：英语考试资料，低价。
5. 生活用品：宿舍台灯，短标题。
6. 生活用品：收纳箱组合，长描述。
7. 代步：校园自行车，高价与长标题。
8. 其他：毕业搬宿舍打包材料，极低价。

所有金额使用整数分；卖家使用独立本机演示用户，避免把演示商品计入现有真实用户内容。

## 写入与清理

新增一个专用脚本，支持：

- `seed`：事务内创建或更新演示用户、8 个商品及对应 approved 审核任务；重复执行不产生重复商品。
- `clear`：事务内仅删除带固定演示标识的审核任务、商品和演示用户；若出现非演示关联数据则拒绝清理。
- `status`：只读打印演示商品数量、分类和状态，不泄露数据库密码。

商品使用一段固定、高位 ID 区间与固定 `open_id` 标识。脚本执行前检查目标数据库和表结构，执行后重新查询并验证恰好存在 8 个公开在售商品。

## 启动与预览

数据写入成功后启动本机 backend；miniapp 继续请求 `http://127.0.0.1:8080/api/v1`。通过公开列表接口确认 8 个演示商品可见，再由微信开发者工具重新编译查看二手市场。

## 失败处理

- 本机数据库不可连接：不写入，给出明确错误。
- DSN 指向非本机：直接拒绝。
- 表结构缺失：不自动运行全库迁移，提示先准备本机开发库。
- 事务中任一步失败：全部回滚。
- 本机 API 端口已被其他进程占用：识别进程后停止，不覆盖其他服务。

## 验收标准

- `seed`、重复 `seed`、`status`、`clear` 均可执行且结果可预测。
- 公开接口返回 8 个演示商品，分类和价格与设计一致。
- 清理后演示商品、演示审核任务和演示用户数量均为 0。
- 现有非演示数据数量与内容不变。
- 不修改或上传线上环境。
