# 管理后台独立密码登录设计

**日期：** 2026-07-24
**状态：** 已获用户逐段确认，待书面规格复核
**范围：** 管理后台认证、网页会话、登录审计、管理员前端登录壳和生产部署
**不在范围：** 小程序普通用户登录、身份申请业务规则、其他后台页面重设计、现有用户提权

## 1. 背景与目标

生产管理后台目前直接读取 `localStorage['domainA.token']`，没有登录页面。管理员必须先通过小程序 `wx.login` 获得 Bearer Token，再手工写入浏览器存储。该方式要求对应微信号能够在微信开发者工具中启动项目，不适合作为永久的生产后台登录方式。

当前业务事实：

- 待审核商家申请为 `01KY9JWJ80C16W3T5G55TDYPT3`；
- 当前申请人是普通用户 `ID 3`，不能审批自己的申请；
- 现有超级管理员为 `ID 1`；
- 管理员接口继续由服务端角色检查保护；
- 用户明确要求不把超级管理员微信号加入小程序项目成员，并选择独立账号密码登录。

本设计目标：

1. 为 `https://zhanduiwang.top/` 提供永久、独立、安全的管理员账号密码登录；
2. 将固定账号名 `administrator` 绑定到现有超级管理员 `ID 1`；
3. 不给普通用户 `ID 3` 提权，不直接修改身份申请状态；
4. 登录成功后通过网页后台使用现有正式管理员接口；
5. 部署完成后通过网页后台审批目标申请，并验证商家授权正式生效。

## 2. 关键约束

- 密码明文不得进入源码、Git、`.env`、日志、命令行参数、终端历史、浏览器存储或聊天记录。
- 网页后台不得继续以 `localStorage` 保存生产管理员凭证。
- 现有小程序 `wx.login`、Bearer Token 和 API 客户端保持兼容，不得破坏当前小程序。
- 管理员角色必须在每次受保护请求时从数据库重新验证，不能只依赖登录时快照。
- 当前工作区已有用户拥有的未提交文件；实现和提交必须精确限定目标文件。
- 不重新设计现有后台视觉体系，只增加必要的登录、账号状态、改密和退出界面。

## 3. 总体架构

新增独立的 `adminauth` 后端模块，负责四件事：

1. 管理管理员密码凭证；
2. 创建、校验和撤销网页会话；
3. 处理登录限速、锁定与 CSRF；
4. 记录认证审计事件。

该模块不替代 `user.Service`，而是通过 `user.Repository` 或明确的最小用户查询接口读取绑定用户，并复用现有 `user.User`、`RoleSuperAdmin`、`StatusActive` 和请求上下文。认证成功后把真实用户写入现有 `domainA.user` 上下文，使现有 `AdminRequired` 和 `SuperAdminRequired` 继续作为最终权限裁决者。

网页管理 API 支持两种认证来源：

- 现有 `Authorization: Bearer <JWT>`：保留给既有客户端、测试和兼容路径；
- 新增安全网页会话 Cookie：供新版管理后台使用。

两种来源最终都必须加载当前数据库用户并执行相同的管理员角色检查。若请求同时携带两种凭证，拒绝模糊认证，不允许静默选择其中一种。

## 4. 数据模型

### 4.1 `admin_credentials`

每个后台账号一条凭证记录：

- `id`
- `username`：唯一，首个账号固定为 `administrator`
- `user_id`：绑定现有 `users.id`
- `password_hash`：Argon2id 编码哈希
- `credential_version`：改密或安全撤销时递增
- `failed_attempts`
- `locked_until`
- `last_login_at`
- `enabled`
- `created_at`
- `updated_at`

约束：

- `username` 唯一；
- `user_id` 唯一且引用真实用户；
- 不保存密码提示、可逆密文或旧密码；
- 禁用凭证后所有会话失效。

### 4.2 `admin_web_sessions`

- `id`
- `session_token_hash`：唯一，仅保存随机会话令牌的 SHA-256 哈希
- `csrf_token_hash`
- `user_id`
- `credential_id`
- `credential_version`
- `created_at`
- `last_seen_at`
- `idle_expires_at`
- `absolute_expires_at`
- `revoked_at`
- `created_ip`
- `user_agent_hash`

原始会话令牌只进入浏览器的 `HttpOnly` Cookie，不写入数据库或日志。原始 CSRF Token 由同源前端读取并仅保存在运行时内存；刷新页面后通过受保护的会话端点重新取得。

### 4.3 `admin_auth_audit_logs`

记录以下事件：

- `login_succeeded`
- `login_failed`
- `login_locked`
- `logout`
- `password_changed`
- `sessions_revoked`
- `session_expired`
- `role_or_status_rejected`

字段包括事件、账号、绑定用户、时间、结果、请求标识、IP 和 User-Agent 摘要。不得记录密码、Cookie、原始会话令牌、原始 CSRF Token 或 JWT。

身份申请的通过／拒绝继续使用现有身份申请事件记录，不在认证审计表重复保存业务详情。

## 5. 密码与首次设置

### 5.1 密码策略

- 长度为 14–72 个字符；
- 允许密码管理器生成的空格和符号；
- 不强制低价值的“大小写＋数字＋符号”组合规则；
- 拒绝与账号名相同或明显弱密码；
- 使用 Argon2id，初始参数为 64 MiB 内存、3 次迭代、并行度 2，并把参数编码进哈希以支持以后升级；
- 比较使用恒定时间实现。

### 5.2 首次凭证设置

新增受控命令，例如：

```text
campus-api admin-credential bootstrap --username administrator --user-id 1
```

命令必须从 TTY 隐藏读取密码并要求输入两次，不接受命令行密码参数，不回显密码，不写入 shell 历史。执行前验证：

- `ID 1` 存在；
- 状态为 `active`；
- 角色为 `superadmin`；
- 当前不存在同名或同用户凭证。

重复执行默认失败；密码重置使用显式的 `reset` 子命令，并撤销全部已有会话。

## 6. 登录与会话流程

### 6.1 登录

`POST /api/v1/admin-auth/login`

请求：

```json
{
  "username": "administrator",
  "password": "<用户输入>"
}
```

流程：

1. 校验请求大小、JSON 结构、Origin 和 Host；
2. 规范化账号名，但不修改密码；
3. 按账号和来源 IP 执行限速；
4. 读取凭证并验证 Argon2id；
5. 重新读取绑定用户，要求 `active + admin/superadmin`，本次首个账号额外要求 `superadmin`；
6. 创建随机网页会话和 CSRF Token；
7. 设置会话 Cookie；
8. 返回最小管理员资料和 CSRF Token。

账号不存在、密码错误、凭证禁用、用户角色不符统一返回“账号或密码错误”，不暴露账号状态。

### 6.2 Cookie

Cookie 名称：

```text
__Host-zhandui_admin_session
```

属性：

- `Secure`
- `HttpOnly`
- `SameSite=Strict`
- `Path=/`
- 不设置 `Domain`
- 不允许前端 JavaScript 读取

默认会话：

- 30 分钟无操作过期；
- 最长 8 小时绝对过期；
- 有效请求可延长空闲过期时间，但不能突破绝对过期时间。

### 6.3 当前会话

`GET /api/v1/admin-auth/session`

返回：

- 当前管理员最小资料；
- 当前角色；
- 绝对过期时间；
- 新的或当前有效的 CSRF Token。

不得返回密码哈希、会话原始值或用户 OpenID。

### 6.4 退出与改密

- `POST /api/v1/admin-auth/logout`：撤销当前会话并清除 Cookie；
- `POST /api/v1/admin-auth/password/change`：验证当前密码，设置新密码，递增凭证版本，撤销全部会话，再要求重新登录。

## 7. 暴力破解防护

- 按账号和来源 IP 双维度限速；
- 连续失败 10 次后锁定 30 分钟；
- 成功登录清除该账号失败计数；
- 对不存在账号执行等价成本的虚拟哈希验证，降低账号枚举和计时差异；
- 所有失败响应使用相同状态和文案；
- Nginx 可增加登录端点的第二层请求频率限制，但业务锁定逻辑必须由后端持久化保证；
- 成功、失败和锁定均写认证审计。

## 8. CSRF 与请求来源

所有使用网页会话的 `POST`、`PUT`、`PATCH` 和 `DELETE` 请求必须同时满足：

1. Cookie 会话有效；
2. `Origin` 为 `https://zhanduiwang.top`；
3. Host 为正式域名；
4. `X-CSRF-Token` 与当前会话哈希匹配；
5. 当前数据库用户仍有管理员权限。

Bearer Token 请求继续沿用现有认证方式，不强制网页 CSRF Token。两种认证来源不得混用。

## 9. 管理后台前端

### 9.1 登录壳

未认证访问后台时只渲染登录页面：

- 账号输入框，默认填入 `administrator`；
- 密码输入框；
- 登录按钮；
- 通用错误提示；
- 登录中状态；
- 锁定或频率限制的通用等待提示。

不提供注册、找回密码或公开创建管理员入口。密码重置必须走受控服务器命令或已登录改密流程。

### 9.2 已登录状态

登录成功后加载现有管理后台。顶部增加：

- 当前管理员账号；
- 会话剩余状态；
- 修改密码；
- 退出登录。

收到 `401` 时清理前端内存状态并返回登录页；收到 `403` 时显示“管理员权限已失效”，不自动重试写请求。

新版网页客户端统一使用 `credentials: 'same-origin'` 和 `X-CSRF-Token`，不再读取 `localStorage['domainA.token']`。兼容 Bearer Token 的后端能力保留，但不在生产 UI 暴露手工 Token 输入。

### 9.3 身份审核

部署当前源码中已存在的「身份审核」栏目，保留：

- 角色和状态筛选；
- 待审核列表；
- 申请资料和证明图片；
- 通过二次确认；
- 拒绝原因输入；
- `expectedRowVersion` 并发控制；
- `409` 后刷新详情。

除登录壳、账号菜单和必要状态提示外，不重新设计其他后台页面。

## 10. 兼容与路由集成

现有管理员业务路径保持不变，例如：

```text
/api/v1/admin/identity-applications
/api/v1/admin/users
/api/v1/admin/media
/api/v1/admin/delivery
```

新增统一认证中间件按以下顺序处理：

1. 检测是否存在 Bearer Token 或网页会话 Cookie；
2. 两者同时存在时拒绝；
3. 分别校验凭证；
4. 读取当前数据库用户；
5. 写入现有 `domainA.user`；
6. 继续执行 `AdminRequired` 或 `SuperAdminRequired`。

小程序用户端路由不接入网页会话 Cookie，避免认证边界扩大。

## 11. 错误处理

- 无效账号或密码：`401`，通用文案；
- 登录锁定或过频：`429`，返回可重试时间但不暴露详细计数；
- 会话缺失、过期或撤销：`401`；
- 管理员状态或角色失效：`403`；
- CSRF 或来源校验失败：`403`；
- 并发身份审批冲突：现有 `409`；
- 数据库或内部错误：`500`，响应不得包含 SQL、哈希、Cookie、令牌或环境配置。

所有响应继续使用项目现有 `{code,message,data}` 信封。

单元和 HTTP 测试覆盖：

- 首次凭证创建和重复创建拒绝；
- Argon2id 正确／错误密码；
- 弱密码和超长请求拒绝；
- 不存在账号的等价成本路径；
- 失败计数、账号锁定和解锁；
- Cookie 完整安全属性；
- 空闲过期和绝对过期；
- 退出撤销；
- 改密撤销全部会话；
- 凭证版本不匹配；
- 用户被禁用、关闭、降级后的即时失效；
- CSRF、Origin 和 Host；
- Bearer 与 Cookie 兼容；
- 两种凭证同时存在时拒绝；
- 审计日志不包含敏感值。

真实 MySQL 集成测试覆盖迁移、事务、会话撤销和管理员身份审批路由。

## 13. 部署与回滚

部署顺序：

1. 数据库备份；
2. 后端向后兼容版本；
3. 数据库迁移；
4. 管理后台静态构建；
5. 首次凭证设置；
6. 服务重启和健康检查；
7. 登录与身份审核生产验收。

回滚：

- 后端和管理后台静态文件恢复上一版本；
- 新增表保留但旧版本不访问；
- 不删除或回滚现有用户、身份申请和身份授权；
- 若凭证已创建但功能回滚，立即禁用凭证并撤销所有网页会话；
- 所有回滚动作写入部署记录。

## 14. 本次目标申请的完成标准

本功能上线并登录成功后，通过正式网页后台审批：

```text
01KY9JWJ80C16W3T5G55TDYPT3
```

完成必须同时满足：

- 申请状态为 `approved`；
- `row_version` 按并发规则递增；
- 审核人是通过密码登录的真实超级管理员 `ID 1`；
- 对应商家身份授权为 `active`；
- 审计和身份申请事件均存在且不含敏感凭证；
- 普通用户 `ID 3` 刷新后能够进入新版商家工作台；
- 未给 `ID 3` 授予管理员或超级管理员角色。
