# 身份切换与配送单剪贴板导入设计

## 目标

在不改变身份审核、角色路由、配送订单状态机、支付开关和服务端数据合同的前提下，完成三项收口：

1. 将学生、骑手、商家之间的身份切换弹窗升级为清晰、克制、适合移动端的角色切换面板。
2. 修复商家工作台“发布配送单”图标的线条叠加与底色冲突，使其与其余快捷入口保持同一视觉体系。
3. 在商家发布配送单页面增加安全的剪贴板批量导入，减少逐项录入，同时避免错误猜测和无确认覆盖。

本次不上传微信版本，不修改后端，不补造订单、联系人、地址或金额。

## 设计原则

- 业务优先：界面调整不能绕过身份审核，也不能改变订单创建与支付能力判断。
- 清晰优先：身份切换只突出“当前身份”和“即将切换到的身份”，删除重复说明和装饰性元素。
- 可恢复优先：剪贴板内容必须先解析、再预览、后确认；取消时不修改表单。
- 真实优先：只导入剪贴板中有明确标签的内容，不从孤立数字或自然语言中猜测电话、地址和姓名。
- 一致优先：继续复用现有 `AppDialog`、`AppActionSheet`、`AppButton`、字段卡片和品牌色，不引入第二套弹窗系统。

## 身份切换面板

### 信息结构

- 标题改为动作式文案，例如“切换到骑手模式”，不再使用疑问句。
- 说明仅保留一行，说明切换后的主界面与返回学生身份的入口。
- 中部使用两个等宽身份卡片：左侧为当前身份，右侧为目标身份，中间使用轻量方向连接符。
- 每张身份卡片包含角色标识、角色名称和状态标签；当前身份使用中性色，目标身份使用品牌色。
- 底部继续使用“取消”和“确认切换”双按钮；确认中、失败和重复点击仍由现有弹窗组件处理。

### 行为边界

- 不修改 `onConfirm`、`onCancel`、`confirming` 和 `error` 的含义。
- 不在弹窗内新增角色申请或审核入口。
- 未审核身份仍由现有身份守卫阻止进入工作台。

## 商家发布配送单图标

- 重绘为单一语义的“配送单据 + 路线箭头”线性图标。
- 图标使用白色线条置于品牌蓝色容器，不再让蓝色 SVG 线条与蓝色底色互相吞没。
- 保持 48×48 视图框、圆角线帽和统一线宽，不使用叠加圆形加号。
- 入口名称、描述和路由保持不变。

## 剪贴板导入

### 页面入口

在商家发布配送单页面的表单顶部增加“批量导入配送信息”卡片，包含：

- “从剪贴板导入”主操作；
- “复制填写模板”辅助操作；
- 一句隐私说明：内容仅在本机解析，确认后才写入表单。

### 支持字段

解析器支持以下明确标签及常用别名：

- `取货联系人`、`取件人`、`商家联系人` → `pickupContact`
- `取货电话`、`取件电话`、`商家电话` → `pickupPhone`
- `取货地址`、`取件地址`、`商家地址` → `pickupAddress`
- `收货人`、`收件人` → `receiverName`
- `收货电话`、`收件电话`、`联系电话` → `receiverPhone`
- `送货地址`、`收货地址`、`配送地址` → `receiverAddress`
- `备注`、`配送备注`、`说明` → `remark`

支持半角或全角冒号、Windows/Unix 换行、字段前后空白，以及地址和备注的续行。出现“取货信息”“收货信息”分段标题后，通用的“联系人”“电话”“地址”按当前分段解析。

### 安全规则

- 空剪贴板或没有识别到任何字段时，只提示，不改变表单。
- 不从无标签文本、孤立手机号或数字中猜测字段。
- 解析成功后使用操作面板展示将导入的字段；用户确认后才覆盖对应字段。
- 只覆盖本次识别到且非空的字段，未识别字段保持原值。
- 取消预览不产生任何副作用。
- 剪贴板全文不会单独上传；只有用户最终提交配送单时，表单字段才沿用现有订单接口。

## 错误与反馈

- 读取剪贴板失败：提示“读取剪贴板失败，请检查授权后重试”。
- 内容为空：提示“剪贴板没有可导入的文字”。
- 无可识别字段：提示使用模板，并保留“复制填写模板”入口。
- 导入成功：提示识别字段数量，并将页面滚动位置保持在当前表单区域。
- 创建订单的校验、支付未开通提示和失败反馈继续使用现有逻辑。

## 验收标准

- 身份弹窗在 iOS、Android 常见宽度下不溢出，角色关系一眼可读，按钮热区不小于现有标准。
- 商家“发布配送单”图标在蓝色底色上清晰，不出现重叠圆圈或线条粘连。
- 复制模板、读取剪贴板、解析预览、取消、确认覆盖均可独立工作。
- 解析器覆盖明确标签、分段通用标签、全角冒号、续行、空内容和无效内容。
- 所有现有订单创建、身份审核、支付开关和真实数据路径保持不变。
- 类型检查、相关静态契约检查、解析器回归、生产构建和全量 `npm run verify` 通过。
- 不上传微信版本；仅生成供用户最终审查和上传的候选产物。
