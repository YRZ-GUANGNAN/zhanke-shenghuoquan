# 湛科生活圈 UI 细节系统升级设计

日期：2026-07-31

## 目标

在不改变业务信息架构、路由、接口合同和真实数据来源的前提下，建立覆盖微信小程序与管理后台的统一 UI 基础系统，并完成全页面细节收敛。最终体验应达到主流成熟应用的基本质量要求：视觉层级清晰、控件行为一致、风险动作可理解、加载和异常可恢复、触控和键盘操作可靠。

## 已批准方案

采用“设计系统优先、渐进精修”，不采用以下两种方向：

1. **逐页零散美化**：短期可见，但会继续复制按钮、弹层、空状态和颜色规则，无法解决跨页面不一致。
2. **整体视觉重写**：变化最大，但会扩大业务回归面，并可能复活此前已经放弃的整套 V5 信息流方向。
3. **设计系统优先、渐进精修（采用）**：先统一 token 与高频基础组件，再替换高风险交互，最后按页面完成比例、密度和状态精修。

用户已批准该方向，并将本轮 UI 细节安排权交由 Codex。实施期间不再对圆角、间距、颜色等常规细节逐项提问；只有涉及业务规则、生产数据、微信上传或外部付费服务时才需要重新确认。

## 现状审计

- 小程序包含 46 个页面与 51 份样式文件，已有 `design-tokens.scss`、胶囊安全标题栏、底部导航和身份切换弹窗，但全局 `app.scss` 与页面样式仍存在另一套颜色、圆角和阴影规则。
- 联系卖家、充值、提现、支付方式、用户操作菜单等底部弹层由多个页面分别实现，遮罩、圆角、关闭按钮、底部安全区和加载行为不一致。
- 部分页面直接调用 `Taro.showModal`，应用内自定义弹窗与微信系统弹窗缺少明确的使用边界。
- 管理后台存在大量浏览器原生 `window.confirm` 与 `window.prompt`，无法提供一致的风险说明、原因校验、处理中状态和错误恢复。
- 管理后台侧栏使用单个字母充当图标，按钮、字段、状态徽标和数据面板已有基础样式，但缺少统一的尺寸、交互状态和响应式收敛。
- 当前功能和发布候选基线已经稳定，因此本轮只改变表现层与交互承载方式，不重写业务逻辑。

## 视觉原则

### 1. 品牌与颜色

- 保留现有蓝白品牌方向，以 `#2E7DD4` 为唯一主行动色，减少同时出现 `#1677FF`、`#2F80D6` 等近似蓝色的情况。
- 页面背景使用冷灰白，内容表面保持纯白；通过边框、轻阴影和间距建立层级，不依赖大面积渐变或装饰图形。
- 成功、警告、危险和信息色只用于语义状态，不能替代品牌色。
- 不生成或填充装饰图片、广告、评分、促销、虚拟头像和虚假内容。

### 2. 字体与信息层级

- 使用系统字体栈，中文优先 `PingFang SC`、`Microsoft YaHei`，保持真机清晰度。
- 建立页面标题、区块标题、正文、辅助说明、标签与数字指标六级文字语义。
- 正文避免过粗；只在页面标题、关键数字和主要操作上使用高字重。
- 长标题、用户名和状态文本必须支持截断或换行，不得挤压头像、关注按钮和微信胶囊安全区。

### 3. 间距、圆角与阴影

- 小程序使用 8rpx 基线网格，后台使用 4px 基线网格。
- 圆角按控件类型分为小、中、大和胶囊四档，禁止页面自行新增近似档位。
- 卡片优先使用细边框和轻阴影；浮层、悬浮按钮和固定操作栏才使用更明显阴影。
- 页面内容宽度、左右留白和区块间距按同一密度规则收敛，避免过度空白或控件贴边。

## 小程序基础组件

### 1. `AppButton`

- 支持 `primary`、`secondary`、`ghost`、`danger`、`text` 五种语义。
- 支持常规、小号、整行、图标按钮、加载和禁用状态。
- 触控高度不低于 88rpx；按下状态通过轻微明度和透明度变化反馈，不使用突兀缩放。
- 加载时保持按钮宽度，禁用重复提交并显示明确动词。

### 2. `AppField`

- 统一单行输入、搜索、多行输入、选择器外观、标签、辅助文本、字数和错误信息。
- 聚焦态显示品牌色边框或柔和外环；错误态不只依赖颜色，还必须显示文字说明。
- 保留微信输入组件的真实行为，兼容键盘顶起、确认键和 iOS 安全区。

### 3. `AppDialog` 与 `AppActionSheet`

- `AppDialog` 用于不可逆确认、身份切换、审核结果等需要用户集中判断的动作。
- `AppActionSheet` 用于支付方式、充值金额、用户菜单等选项集合。
- 统一遮罩、层级、进入和退出动效、关闭规则、底部安全区、标题、说明与按钮布局。
- 提交期间锁定遮罩关闭和重复操作；失败时保留用户输入并在浮层内部显示错误。
- `Taro.showModal` 仅保留给微信平台级提示，例如版本更新；业务动作迁移到应用内组件。

### 4. `AppState`、`AppNotice` 与 `AppSkeleton`

- `AppState` 统一加载、空、错误、无权限和离线状态，可携带一个主要动作和一个次要动作。
- `AppNotice` 统一页面内的信息、成功、警告与危险提示，不再用孤立纯文本表达关键状态。
- 列表、详情、个人主页和工作台使用与最终布局近似的骨架屏，避免整页白屏和布局跳动。
- API 失败不得回退到旧假数据；保留现有内容并提供可重试状态。

### 5. 图标与导航

- 扩展现有 `AppIcon`，统一图标画布、线宽、圆角端点和光学居中。
- 图标只表达动作，不使用难辨认的字符或表情符号替代。
- 胶囊标题栏继续为微信系统胶囊独占一行；业务标题、搜索、返回和右侧操作全部位于安全区域。
- 底部导航保持现有五项结构，统一按下、激活、禁用和未读状态。

## 管理后台基础组件

### 1. 管理操作组件

- 建立 `AdminButton`、`AdminField`、`AdminSelect`、`AdminBadge`、`AdminNotice` 和 `AdminState`。
- 统一高度、边框、焦点环、禁用和加载状态；危险操作不得使用主按钮蓝色。
- 表格行内操作按“主要、次要、危险”排序，避免多个按钮同权竞争。

### 2. `AdminDialog`

- 全面替换 `window.confirm` 与 `window.prompt`。
- 支持确认、原因输入、危险确认和操作结果四类场景。
- 拒绝、下架、清账等需要原因的动作必须在弹窗中完成必填校验。
- 服务器失败时弹窗不消失，保留原因和选中对象；成功后关闭并刷新对应数据。

### 3. 后台导航与数据布局

- 将侧栏字母图标替换为统一的线性 SVG 图标，不引入新的大型图标库。
- 统一顶部标题、筛选栏、指标卡、数据表、详情抽屉与分页的层级。
- 宽屏保持高效数据密度；较窄窗口允许表格横向滚动、筛选换行和详情面板收缩，不隐藏业务字段。
- 登录、修改密码、会话失效和无权限状态使用同一视觉语言。

## 页面级精修范围

### 小程序

- 首页、搜索、帖子详情与公开主页：收紧作者区、关注按钮、标题正文、标签、元数据和互动栏比例；保留真实信息流和现有功能。
- 二手列表、商品详情、发布、留言与私信：统一商品卡、价格、状态、卖家信息、底部操作栏和联系弹层。
- 我的、我的内容、设置、黑名单、反馈与资料编辑：统一列表行、分段标签、空状态、表单和危险操作。
- 商家与骑手工作台、订单、钱包和身份申请：统一指标、状态标签、任务卡、表单、弹层和审核反馈。

### 管理后台

- 登录和账户安全。
- 媒体、配送、统计、用户、身份、统一审核、帖子、商品、举报与导航管理。
- 每个模块至少具备稳定的加载、空、错误、处理中、成功和冲突状态。

## 交互与动效

- 动效时长分为快速反馈、标准过渡和浮层过渡三档，使用统一缓动曲线。
- 支持系统减少动态效果偏好；不使用大面积位移、弹跳或持续动画。
- 所有异步写操作必须有进行中状态、防重复提交和结果反馈。
- 删除、拒绝、下架、注销等危险动作采用明确对象名称和后果说明，不使用含糊的“确定吗”。
- Toast 只用于轻量结果；需要用户判断或纠错的内容必须留在页面或弹窗中。

## 可用性与无障碍

- 小程序触控目标不小于 44px 等效尺寸，后台键盘焦点清晰可见。
- 文本与背景保持可读对比度；状态不能只依靠颜色区分。
- 弹窗打开后后台不可误触，关闭后焦点回到触发控件。
- 图片具有真实空状态；图像加载失败时显示中性占位和简短说明。
- 支持长文本、系统大字体、iOS 刘海和底部安全区、Android 键盘与不同窗口宽度。

## 实施顺序

1. 补齐设计 token 与视觉契约检查。
2. 构建小程序基础组件并迁移共享导航、会话状态和身份切换。
3. 迁移小程序全部自定义弹层和平台级弹窗边界。
4. 精修学生端高频页面，再处理商家端、骑手端和设置类页面。
5. 构建管理后台基础组件和统一对话框，替换所有原生确认与输入框。
6. 收敛后台导航、表格、筛选、详情和账户页面。
7. 运行合同检查、类型检查、构建、后端回归与视觉边界检查，形成最终交付清单。

## 验收标准

1. 小程序和管理后台不再存在未批准的近似品牌蓝、随意圆角和页面自定义高层级遮罩。
2. 小程序业务弹层统一使用共享组件，平台级 `Taro.showModal` 使用点有明确白名单。
3. 管理后台不存在 `window.confirm` 和 `window.prompt`。
4. 主要异步操作均具备加载、禁用、成功和错误状态，失败时不丢失输入。
5. 胶囊安全区、底部安全区、软键盘和较窄后台窗口通过布局合同检查。
6. `npm run typecheck`、`npm run verify`、`npm run build:miniapp`、`npm run build:admin` 和 `git diff --check` 通过。
7. 不引入假数据、生成图片、广告或未经批准的业务入口。
8. 最终构建产物留在本地，由用户自行在微信开发者工具上传。

## 非目标

- 不重写后端、数据库、审核策略、支付、腾讯云 IM 或企业微信通知合同。
- 不改变底部导航、身份体系、审核入口和管理后台模块划分。
- 不把已放弃的 V5 信息流或参考应用的品牌、素材和具体布局重新带回项目。
- 不在本轮处理现有 `vendors.js` 体积警告，除非实现过程中出现新的阻断性增长。
- 不写生产数据、不修改微信后台配置、不上传体验版或正式版。
