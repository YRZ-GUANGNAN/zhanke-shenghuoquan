## 方案选择

- **采用：局部排版 + 状态可靠性。** 清楚区分个人资料、内容、角色工作台、账户支持；修复计数失败、动态栏目留空和切栏丢进度。
- 仅改样式：风险更低，但保留了请求失败显示 0、固定列数和列表重复读取的问题，因此不作为完整试验方案。
- 重建作者型主页：不符合账号中心用途，也会扩大既有功能和角色权限范围，因此不做。

## 首版实现

### 我的主页

- 继续使用现有蓝色令牌、系统中文字体、既有 AppIcon 与 StudentBottomNav，不动共享样式。
- 资料头保留真实头像/昵称/身份/用户号/学校；微信胶囊留白不再是编辑点击区；真实头像失败回退昵称首字，不接入新图片。
- 容器连续白底，32rpx 外边距，主要节奏 16/24/32rpx。章节用弱分隔与排版组织，不叠加卡片阴影。
- 内容栏目按实际可见数量均分；所有既有栏目、URL 与服务端开关语义保留。
- 社区和二手计数独立读取；未读取显示 `—`，真实 0 才显示 0；一端失败不丢另一端结果，返回后台刷新失败时保留已知值并提示重试。
- 身份入口保持原申请/切换确认/历史订单逻辑；采用可读性更高的行式布局，完整显示身份状态与说明。
- 导航与角色确认增加同步防重，失败后可重试。账户变化时清除上个账号的临时显示状态。

### 我的内容配套

- 保留收藏/帖子/评论/宝贝四个既有栏目及对应接口，不新增标签。
- 每栏各自维护内容、分页、错误及滚动位置；切换回来不清空已读列表。
- 首次加载失败与分页/返回刷新失败分别显示；后者保留已有正文。重复触底只发送一次请求。
- 详情返回静默刷新当前已加载范围；原滚动位置保持，由真实内容删除导致的缩短交给原生滚动容器限界。
- 功能关闭或账号变化立即隔离旧请求与缓存；不允许旧响应重新显示已关闭内容。
