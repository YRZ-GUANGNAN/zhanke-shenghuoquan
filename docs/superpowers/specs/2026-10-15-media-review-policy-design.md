# 图片用途与审核分流

## 已确认范围

用户最终要求：二手和帖子自动审核；头像、个人主页封面可以直接更换；骑手、商家申请由管理网站人工审核。本要求替代此前将公开资料图片也交给人工审核的选择。继续在隔离分支 `codex/media-review-policy-20261015` 实施，基线 `5e60cae`。保留两份用户修改的 project 配置，不修改原项目，不在本轮部署。

## 文档依据与选择

已核对项目媒体设计、身份申请设计、2026-07-29 混合自动审核设计及真实实现。参考资料库 `b621e35` 明确说明未还原服务端审核机制，不能把客户端即时显示作为平台免审规则的依据。本次是项目自己的用途策略，不声称微信提供审核豁免。

相比全局关闭审核（会放开帖子、商品），或所有图片再走人工队列（不符合最终要求），采用服务端明确的用途分流。客户端不得上传一个“跳过审核”参数。

| 用途 | 图片可用条件 | 最终业务生效 |
| --- | --- | --- |
| post / product | 文件校验完成且云图片检查通过 | 正文自动检查通过后发布；风险不公开 |
| avatar / profile_cover | 文件校验完成，服务端标记 not_required | 本人保存后替换；失败保留旧图 |
| identity_application | 文件校验完成，服务端标记 not_required | 只允许提交私有材料；管理员通过申请后才授予角色 |
| 其他图片用途 | 保留原规则 | 保留原业务规则 |

## 媒体状态与隐私

新增审核投影终态 `not_required`，准确表示该用途不需要单独图片内容审核；不伪造微信通过、人工审核人或审核决策。它不是可由回调提交的审核结果。只有三种明确用途可获得该状态，其他用途仍必须 `approved`。所有绑定和展示同时校验最终固定对象、用途、所有者、未删除、有效引用和父对象可见性。

新上传由投影创建事务依据资产真实用途记录策略状态。旧待审核/已拒绝记录不批量改写，不复活已拒绝图片；重新选择上传即可走新策略。旧审核回调不能改变新的策略终态。历史已通过资产继续可用。垃圾回收对该终态使用正常可用图片的保留期。

小程序新增 `ready` 状态，显示“已上传，保存后生效”或“材料已上传，提交后由管理员核验”。不再让资料图片等待 90 秒审核轮询。身份证明仍仅经管理员鉴权、精确申请绑定和短期签名读取，公共媒体解析入口仍拒绝。

## 自动审核

保留并验证帖子、商品的真实云检测与自动决定；明确安全才发布，明确风险拒绝。模糊结果不公开，异常不作为通过。修复当前文本检查将缺失 suggest 当成 pass 的问题。异常处理须可恢复，不能通过删除校验或使用本地 mock 自动批准来实现。

## 头像保存链路

审查发现头像上传已经使用新媒体域，但资料保存仍只调用旧媒体接口。补齐新资产的绑定、发布、旧引用撤销与资料保存事务；封面继续使用已有独立事务。昵称、学校、校区及旧头像/封面互不覆盖，已有身份和禁言守卫继续有效。

## 验证与交付

覆盖用途分流、禁止伪造免审用途、上传校验失败、云回调、帖子/商品待审不可见、头像/封面持久化和并发替换、旧图保留、身份证明私有解析与人工授予角色。运行后端测试、隔离 MySQL 集成测试、前端行为检查、类型检查和构建。生产是否已生效必须与本地完成分开报告。

自审：不新增商品/社区功能，不自动批准身份，不更换存储，不改业务开关，不把上传成功称作审核通过，不将参考平台的客户端行为当作官方规定。
