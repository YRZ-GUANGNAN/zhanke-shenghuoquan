# 小程序业务修复、分域搜索与设置闭环设计

## 背景

当前体验版已能正常加载数据和上传图片，但仍存在以下阻断性问题：帖子发布返回错误；外卖页内容重叠且使用静态商家数据；“我的”与设置页包含缺失或静态功能；“关于湛科生活圈”无法进入完整页面；搜索没有真实数据能力；热词和帖子标签不会根据实际使用更新；学生端发布入口错误地展示“发布配送单”。

本次按“先业务、后 UI”的顺序处理。所有业务功能完成并通过验证后，再统一进行视觉美化；最后执行一次完整回归并只上传一个新的微信体验版本。

## 已确认决策

1. 采用分模块完整实现，不使用仅前端本地过滤，也不使用可能混淆数据的全局搜索。
2. 帖子、二手、外卖分别拥有独立搜索范围、历史记录和热词统计。
3. 热词使用最近 7 天滚动窗口，近期搜索权重更高。
4. 搜索结果先按关键词匹配度排序；匹配度相同时，较新、较热门的内容优先。
5. 自定义标签仅用于帖子，每篇帖子最多 3 个标签。
6. 标签热度以使用量为主，以点赞、评论、收藏等互动为辅，并随时间衰减。
7. 学生端发布入口仅保留“发布帖子”和“发布二手”。
8. 账号注销为直接注销；存在未完成订单、退款或余额处理时必须阻止注销。
9. 注销后历史帖子和评论匿名保留，作者显示为“账号已注销”。
10. 全部业务完成并验证后才开始 UI 美化，最终统一上传一个体验版本。

## 目标

- 修复帖子发布失败，保持图片审核、媒体绑定和幂等写入链路。
- 建立帖子、二手、外卖三个互不混合的搜索闭环。
- 建立按真实搜索频率更新的模块热词，以及按真实使用和互动更新的帖子标签。
- 将外卖页接入后台商家目录并能够打开对应商家小程序。
- 补齐“我的”、设置、黑名单、反馈、关于和账号注销等真实功能。
- 移除学生端不应出现的配送单发布入口。
- 在不提前重做视觉样式的前提下，修复影响操作的页面重叠和状态反馈问题。

## 非目标与硬边界

- 业务阶段不进行配色、卡片风格、动效或品牌视觉重做；仅允许为保证可操作性而修改布局。
- 不把帖子、二手、外卖合并为全局搜索，也不允许缺失搜索范围时回退到全局数据。
- 不将自定义标签扩展到二手商品或外卖商家。
- 不新增学生发布配送单的替代入口。
- 不降级微信小程序基础库，不绕过微信授权，不在客户端保存微信敏感凭证。
- 数据库迁移只向前增加或兼容性修改，不破坏现有订单、帖子、二手商品、商家目录和媒体数据。
- 账号注销不会物理删除必须保留的数据关系；对外身份立即失效，公开作者信息匿名化。
- 本地测试、构建或接口测试通过不等于真机和微信体验版验收通过。

## 1. 帖子发布修复

### 现状原因

社区发布客户端当前生成的 `clientRequestId` 不符合后端要求的 26 位 Crockford ULID，导致 `POST /community/posts` 返回 400。图片上传和媒体完成接口本身可成功，因此修复应聚焦于发布请求契约，不回退或绕过媒体审核。

### 目标行为

1. 社区发布与二手发布复用项目内唯一的合法客户端 ULID 生成器。
2. 同一次逻辑提交将同一 ULID 同时写入请求体 `clientRequestId` 与请求头 `Idempotency-Key`。
3. 网络失败后的原样重试复用原 key；用户修改内容、收到幂等冲突或发布成功后，下一次逻辑提交生成新 key。
4. 提交中禁用重复点击；失败时保留文字、标签和已上传图片，便于重试。
5. 201 创建成功与 200 幂等重放都视为成功；400、409、401/403、5xx 分别展示可理解且不伪造成功的反馈。
6. 已完成的图片上传继续通过现有媒体引用绑定进入帖子，不使用本地临时路径代替资产 ID。

## 2. 分域搜索

### 搜索范围

| 模块 | 可搜索字段 | 明确排除 |
|---|---|---|
| 帖子 | 标题、正文、标签 | 二手商品、外卖商家 |
| 二手 | 商品标题、描述、分类 | 帖子、外卖商家 |
| 外卖 | 商家名称、商家简介 | 帖子、二手商品 |

### 页面与路由

- 各业务页进入搜索时必须携带明确的 `scope`：`community`、`secondhand` 或 `takeout`。
- 前端可以复用搜索页面和展示组件，但必须按 `scope` 调用对应领域服务。
- 缺失、空白或非法 `scope` 时显示“搜索入口无效”，不请求任何全局或默认业务数据。
- 搜索输入、历史、热词、结果、空状态、加载失败和重试均保持当前模块语义。

### 历史记录

- 每个已登录用户在每个模块分别保存最近 20 条确认搜索。
- 仅在用户点击搜索、键盘确认或点击建议词后记录；输入过程不计入历史或热度。
- 同一模块中的相同关键词归一化后去重并更新最近使用时间。
- 用户可单独清空当前模块历史，不能一次操作误删其他模块历史。
- 客户端只缓存可重建的展示副本，服务器记录是跨设备恢复的来源。

### 关键词归一化与防污染

- 去除首尾空白、合并连续空白，英文按不区分大小写匹配。
- 空关键词不记录，归一化后长度限制为 1–50 个可见字符。
- 同一用户、同一模块、同一关键词在 30 秒内重复确认，只计一次热度事件，但仍可正常返回结果。
- 同一用户对同一模块、同一关键词每天最多贡献 5 次公开热度，超过后仍保留正常搜索能力，但不再增加热词分数。
- 热词聚合不公开用户身份，只返回关键词、展示顺序和必要的趋势状态。

### 热词规则

- 帖子、二手、外卖各自维护最近 7 天的确认搜索事件。
- 按距今天数使用固定日级权重：当天为 7，前 1 天为 6，依次递减，前 6 天为 1；窗口外为 0。
- 排序依次比较衰减后的搜索分、原始搜索次数和最近搜索时间。
- 归一化关键词在窗口内至少有 3 次有效确认且来自至少 2 个不同用户，才进入公开热词。
- 每个模块默认返回前 10 个热词；服务端可下调返回数量，但不得超过 20 个。
- 点击热词视为一次确认搜索，并进入当前模块历史和统计。

### 搜索结果排序

1. 关键词匹配度：标题或名称的完整匹配、前缀匹配优先于正文或简介匹配。
2. 内容新鲜度：匹配度相同时，最近发布或最近更新的内容优先。
3. 内容热度：仍相同时，帖子按互动、二手按收藏或浏览、外卖按目录顺序及可用状态稳定排序。
4. 使用稳定的唯一 ID 作为最后排序键，避免翻页期间顺序抖动。

### 搜索可见性

- 帖子搜索只返回审核通过且当前可公开的帖子；排除审核中、审核拒绝、已删除、已屏蔽内容，以及当前用户已拉黑作者的内容。
- 二手搜索只返回在售且可公开的商品；排除已售、已下架、已删除、审核不可见商品，以及当前用户已拉黑卖家的商品。
- 外卖搜索只在商家目录总开关开启时工作，并只返回后台设为可见的商家；营业中、休息中和已打烊均可展示，隐藏商家不返回。
- 搜索接口不得因为用户是内容作者或后台管理者而在学生端泄露非公开内容；管理端查询使用独立接口。

### 服务边界

- 帖子搜索、帖子历史和帖子热词归 `community` 领域。
- 二手搜索、二手历史和二手热词归 `trade` 领域。
- 外卖搜索、外卖历史和外卖热词归 `navigation` 领域。
- 三个领域可以复用无状态的关键词规范化工具，但不共享带业务含义的默认范围或查询入口。
- 本次不引入新的外部搜索服务；先使用现有数据库和有界查询满足体验版规模，后续扩容另行设计。

## 3. 帖子自定义标签与热门标签

### 创建规则

- 发布帖子时可从热门标签中选择，也可输入自定义标签。
- 每篇帖子最终标签数量为 0–3 个。
- 单个标签去除首尾空白和多余的前导 `#`，限制为 1–12 个可见字符。
- 归一化后完全相同的标签只保留一个；空标签、控制字符和超长标签由前后端共同拒绝。
- 标签只绑定社区帖子，不写入二手或外卖数据结构。

### 热度规则

- 仅统计最近 7 天内处于可公开状态的帖子及其互动。
- 标签使用分是第一排序因素。每个公开帖子对其标签贡献一次使用事件，并按距今天数使用 7、6、5、4、3、2、1 的固定权重。
- 使用分相同时再比较互动分：点赞每次计 1、评论每次计 2、收藏每次计 2，并使用同一套日级权重。
- 被删除、审核拒绝或不可见帖子的标签及互动不进入公开热榜。
- 排序最后使用最近使用时间和标准化标签文本，保证结果稳定。
- 热门标签默认返回前 12 个，最多不超过 20 个。

## 4. 外卖商家目录

### 数据来源

- 删除学生外卖页中的静态商家数组，调用现有外卖商家目录服务。
- 使用后台已经维护的 `title`、`subtitle`、`iconText`、`color`、`appId`、`path`、`sort` 和 `operatingStatus`。
- 分类总开关关闭时显示“外卖商家暂未开放”；商家不可见时不出现在学生端。

### 展示与跳转

- “营业中”商家可点击，使用 `Taro.navigateToMiniProgram` 按后台提供的 `appId + path` 打开商家小程序。
- “休息中”或“已打烊”商家仍可展示，但操作按钮置灰并说明状态，不执行跳转。
- 跳转参数只使用服务端已校验并返回的目录值，不接受页面参数覆盖 `appId` 或 `path`。
- 跳转失败时保留当前页面并显示可重试反馈，不显示“已打开”等假成功提示。

### 可用性修复

- 重新计算顶部栏、搜索区域、滚动列表和底部导航的安全间距。
- 列表内容不得被固定顶部或底部区域遮挡；短屏和大字号下仍能滚动到最后一家商家。
- 加载中、空目录、目录关闭、网络失败和重试分别显示明确状态。
- 视觉色彩、卡片造型和动效在业务验收后统一美化，本阶段不提前换肤。

## 5. 学生端发布入口

- 学生端“＋”只展示“发布帖子”和“发布二手”。
- 删除“发布配送单”卡片、文案和路由触发，不使用仅隐藏样式的方式保留可点击区域。
- 配送单发布仍属于商家或配送业务入口；本次不删除其合法业务页面和后端能力。
- 增加页面级测试，验证学生发布入口中不存在配送单选项。

## 6. “我的”、设置与关于

### 手机号绑定与更换

- 设置页读取服务器真实绑定状态，不显示写死手机号。
- 未绑定时提供微信手机号授权入口；已绑定时只显示脱敏号码并允许重新授权更换。
- 客户端只提交微信提供的一次性授权凭据，手机号解析和保存由服务端完成。
- 用户拒绝授权、授权过期、号码冲突或服务失败时保持原状态并显示对应反馈。

### 身份状态

- 读取现有身份接口，展示当前身份以及学生、骑手、商家身份的真实可用状态和原因。
- 不把“当前是学生”伪装成已经完成某种不存在的校园认证。
- 身份切换继续使用现有受保护流程，设置页只展示状态并提供合法入口。

### 消息与隐私设置

- 订单通知、互动通知、夜间免打扰及现有隐私开关保存到服务器用户设置。
- 微信系统通知权限与应用内偏好分开表达：应用开关控制平台是否尝试发送，不能伪装成已经获得微信系统授权。
- 设置加载失败时保留上一次已确认状态；保存失败时回滚开关并提示重试。

### 黑名单

- 黑名单页读取真实用户关系和真实人数，支持解除拉黑。
- 解除操作失败时不提前移除列表项；成功后同步更新设置页人数。
- 空列表、加载失败和重试均有独立状态。

### 清理缓存与检查更新

- 清理缓存只清除图片缓存、模块搜索历史副本等可重建数据，不删除登录令牌、身份选择和必要运行配置。
- 清理前显示实际可清理大小，成功后重新计算并展示结果。
- 检查更新接入微信小程序更新管理能力；无更新、存在更新、下载完成和失败分别反馈。

### 意见反馈

- 新增反馈页面，包含问题类型、文字描述和最多 3 张图片凭证。
- 图片继续通过受控媒体上传、审核和业务绑定，不把本地路径写入反馈记录。
- 提交中禁止重复点击；成功返回可追踪的反馈编号，失败保留输入便于重试。
- 管理端或后端至少能够查询反馈及其状态；本次不扩展为实时客服系统。

### 关于湛科生活圈

- 新增可正常进入的独立页面，展示产品介绍、当前版本、用户协议、隐私政策和联系／反馈入口。
- 协议和隐私政策复用现有法务页面，不复制两份可能产生版本漂移的正文。
- 页面中的下一步入口必须有真实路由，不使用静态 Toast 代替。

### 直接注销

- 注销入口位于设置页的危险操作区，必须经过两次明确确认。
- 服务端在执行前检查所有配送／外卖非终态订单、进行中的退款或提现、可用余额大于 0、冻结余额大于 0；任一存在时返回具体阻断原因，不注销账号。各领域的终态枚举在实施计划中按现有模型逐项列出并测试。
- 条件满足时立即撤销现有会话和登录凭证，使账号退出且不可继续使用。
- 原账号保留不可登录的注销墓碑记录；昵称、头像、手机号及其他可删除的私有资料清空或匿名化，手机号唯一占用被释放。
- 用户设置和由该用户发起的黑名单关系删除；其他用户指向该账号的黑名单关系随注销墓碑失去公开身份，不再显示个人资料。
- 历史帖子和评论保留，作者统一显示“账号已注销”；注销前发布的内容不会归属给未来新账号。
- 在售二手商品下架；已售或历史商品按业务一致性保留并匿名显示卖家。注销账号不能再创建交易或会话；既有订单和必要审计关系保持一致。
- 同一微信身份或原手机号以后可以显式注册为一个全新的账号，但必须再次确认注册并获得新的用户 ID；不得静默恢复注销账号，也不得把旧内容重新关联给新账号。
- 反馈和必要审计记录按注销账号 ID 保留最小关联，不在学生端公开个人资料。
- 注销成功后客户端清除本地会话并回到登录入口；任何失败均不得提前清除本地状态或显示成功。

## 7. 数据与迁移

### 建议的数据归属

- `community`：帖子搜索历史／事件、帖子标签、标签关联和标签聚合查询。
- `trade`：二手搜索历史／事件。
- `navigation`：外卖搜索历史／事件；商家目录继续使用现有系统分类。
- `user`：用户设置、手机号绑定状态、黑名单关系、反馈、注销状态和会话撤销信息。

### 迁移约束

- 使用新的、顺序递增的向前迁移文件。
- 新增字段必须有安全默认值，避免旧用户加载失败。
- 为用户、模块、规范化关键词和时间窗口建立必要索引，但不在共享业务表上执行破坏性重建。
- 热词和标签排行可以从事件或关联表重算，不把缓存排行作为唯一事实来源。
- 在临时独立数据库中验证迁移；没有创建数据库权限时明确标记为权限阻断，不对共享数据库执行破坏性替代测试。

## 8. 接口与错误约定

- 列表和搜索使用有界分页，服务端限制 `pageSize`，客户端支持稳定加载更多。
- 记录搜索、保存设置、反馈提交和注销等写操作使用鉴权，并对重复提交提供幂等或等价保护。
- 400 表示输入不合法，401/403 表示登录或权限问题，404 表示目标不存在，409 表示状态或幂等冲突，5xx 表示可重试的服务异常。
- 客户端不得把非 2xx 当作成功，不得在失败后乐观保留错误状态。
- 日志记录请求 ID、模块和错误类别，不记录手机号明文、微信授权凭据或搜索用户身份明细。

## 9. 验收标准

### 帖子发布

- 带图片和不带图片的帖子均可真实发布；请求 ID 为合法 ULID。
- 连续点击或网络重试不会重复创建帖子；错误后表单内容不丢失。

### 搜索与热词

- 从帖子页搜索只出现帖子，从二手页搜索只出现二手商品，从外卖页搜索只出现商家。
- 三个模块的历史和热词互不影响，清空一个模块不会删除其他模块数据。
- 构造跨 7 天测试数据后，近期高频词按规则靠前；输入过程和短时重复确认不会污染统计。
- 匹配度、新鲜度、热度和稳定排序均有后端测试覆盖。

### 标签

- 帖子可添加 0–3 个合法标签；重复、超长和非法标签被正确处理。
- 热门标签随最近 7 天的真实发帖和互动变化，不统计不可公开帖子。
- 二手和外卖数据结构、页面和搜索中不出现社区自定义标签能力。

### 外卖

- 页面展示后台真实商家目录；商家状态和排序与后台一致。
- 营业中商家可打开目标小程序；非营业状态不误跳转。
- 顶部、列表和底部导航在常见真机尺寸下不重叠，最后一项可完整操作。

### 设置与账号

- 手机号、身份、通知、隐私、黑名单人数均来自真实服务，不显示写死数据。
- 缓存清理不导致退出登录；更新检查返回微信运行时的真实状态。
- 反馈可提交文字和审核后的图片，并返回反馈编号。
- “关于湛科生活圈”及其协议、隐私、反馈入口都可正常到达。
- 无未结业务的用户可直接注销并立即失去访问权限；存在阻断业务的用户无法注销且收到明确原因。
- 注销用户的帖子和评论仍存在，但作者匿名；在售二手商品已下架。

### 发布入口

- 学生端“＋”仅有帖子和二手两个入口；不存在配送单文案、卡片或可点击区域。

## 10. 验证顺序与门禁

1. 后端领域单元测试和仓储测试。
2. 迁移静态检查与独立临时数据库验证。
3. 前端服务契约测试、页面交互测试、类型检查和微信构建。
4. 本地 API 与小程序开发者工具联调。
5. 真实微信环境验证手机号授权、更新管理和外部小程序跳转。
6. 所有可在当前环境执行的业务测试通过后开始 UI 美化；如果真机、微信权限或外部商家环境暂不可用，对应项目保持 `PENDING`，但不阻塞其他非依赖工作和 UI 美化。
7. UI 美化完成后重复关键业务回归和多尺寸布局检查。
8. 上传条件可用时上传一个新的体验版本并在真机复测；上传前必须通过全部本地自动化、构建和可执行的开发者工具检查。

真机、微信权限、外部商家小程序或线上部署条件不可用时，相应项目保持 `PENDING`，不得用本地测试结果替代。`PENDING` 不会被标记为通过；体验版上传后仍需保留待验清单，直至真机确认或明确失败。

## 11. 实施计划拆分

本设计是一个统一业务目标，但不作为单个超大实施计划直接执行。用户批准本设计后，按以下依赖顺序分别生成可执行计划：

1. **发布与学生入口计划：** 修复社区 ULID／幂等发布，移除学生配送单入口。
2. **分域搜索与帖子标签计划：** 完成三个领域的搜索、历史、热词以及社区标签。
3. **外卖商家目录计划：** 接入动态目录、独立商家搜索、状态处理、跳转和必要布局修复。
4. **用户设置与注销计划：** 完成手机号、身份状态、持久化设置、黑名单、反馈、关于和直接注销。
5. **业务总验收计划：** 统一迁移验证、接口联调、微信构建、开发者工具和真机待验清单。
6. **UI 美化计划：** 仅在可执行业务门禁通过后单独设计和实施。
7. **最终回归与体验版计划：** 重跑完整验证并只上传一个体验版本。

每个计划必须列出准确文件、现有接口复用点、测试命令和提交边界；前一计划产生的稳定契约是后一计划的输入，不允许并行修改同一领域契约。

## 12. UI 美化阶段边界

业务验收完成后，单独制定 UI 美化方案。该阶段可以统一处理色彩、字号、间距、卡片、空状态插图和动效，但不得改变本设计已冻结的搜索范围、发布入口、标签规则、外卖跳转、设置语义和注销约束。视觉调整完成后必须重新执行本设计中的完整验收链路。

## 13. 风险与缓解

- **搜索热度被刷：** 仅记录确认搜索，做短时去重、输入校验和最小公开阈值。
- **搜索数据串域：** 路由和服务端都校验模块范围，非法范围失败关闭，不回退全局搜索。
- **帖子重复发布：** 修复 ULID 并保持 `clientRequestId` 与 `Idempotency-Key` 一致。
- **外部小程序不可达：** 只使用后台已校验目标，处理非营业状态和跳转失败。
- **微信授权受运行环境限制：** 开发工具测试之外保留真机验收，不伪造绑定成功。
- **误注销：** 两次确认、服务端未结业务检查、失败不清理客户端会话。
- **并行改动冲突：** 实施前检查工作树和独立 worktree，按领域拆分提交并避开无关用户改动。
