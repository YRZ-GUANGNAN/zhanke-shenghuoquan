# 湛科生活圈生产发布设计

## 目标与发布范围

将隔离分支 `codex/campus-services-review` 中已经提交的后台管理完善、反馈表映射修复和小程序 AppID 切换发布到现有生产环境，同时保持原工作区与当前未提交的小程序文件不受影响。

本次发布包含三项独立产物：

1. Linux amd64 后端二进制，带版本、提交和构建时间信息。
2. 后台管理站点静态文件，由 Nginx 从 `/var/www/campus-admin/current` 提供。
3. 微信小程序生产构建，API 固定指向 `https://zhanduiwang.top/api/v1`，AppID 为项目已提交的新 AppID。

本次不包含当前工作区中四个未提交的小程序 UI 文件，也不包含 `artifacts/`。不修改业务接口、身份守卫或生产数据库数据。

## 发布方案比较

### 方案 A：版本目录加原子软链接切换（采用）

从提交后的干净临时 worktree 构建，在服务器创建带时间戳和 Git 短哈希的后端与后台版本目录。文件完整上传并校验后，再一次性切换 `current` 软链接，重启后端并执行健康检查。失败时把软链接切回发布前目标。

优点是产物可追踪、切换窗口短、回滚明确，并与服务器现有目录结构一致。

### 方案 B：原地覆盖当前文件（拒绝）

直接覆盖正在运行的二进制和后台静态文件。步骤少，但上传中断会留下半套文件，后台资源也可能出现新旧混用，回滚困难。

### 方案 C：Git 远程或 CI/CD（本次不可用）

仓库当前没有配置 Git 远程，也没有可用的生产流水线定义。本次不临时引入新托管和权限体系。

## 安全边界

- 发布源固定为本次文档提交后的 Git `HEAD`，通过临时 worktree 获得干净快照。
- 仅精确提交本次发布文档；不暂存或修改用户已有脏文件。
- AppSecret 只从 Git 忽略的 `backend/.env` 读取，通过标准输入写入服务器临时文件；不出现在命令参数、Git、构建产物和日志中。
- 服务器更新环境变量前创建权限为 `0600` 的备份；只更新 `WECHAT_APP_ID`、`WECHAT_APP_SECRET` 与 `ALLOW_MOCK_WECHAT_LOGIN` 三项。
- 当前迁移目录没有新增生产迁移，服务器现有发布已包含最新 `037_report_idempotency.sql`，因此本次不执行数据库迁移。
- 不改写外部商家记录中的 `appId` 或跳转路径。

## 发布顺序与回滚

1. 记录线上 `/version`、三个服务状态和两个 `current` 软链接目标。
2. 从干净提交运行契约检查、类型检查、后端测试和生产构建。
3. 上传后端与后台到新的不可变版本目录，校验后端 SHA-256。
4. 备份并更新服务器微信环境变量，切换后端软链接，重启 `campus-api`。
5. 在服务器本机验证 `/healthz`、`/readyz`、`/version`；从公网验证 `/healthz` 与 `/version`。
6. 后端通过后切换后台软链接，执行 Nginx 配置检查和首页/API 冒烟检查。
7. 使用微信开发者工具上传小程序开发版本。上传成功不等于审核或正式发布；微信公众平台要求的提交审核和发布环节必须遵守平台状态机。

若后端检查失败，立即恢复旧后端软链接、旧环境文件并重启；若后台检查失败，只恢复旧后台软链接。新版本目录保留用于诊断，不删除旧版。

## 验收标准

- 后端 `/version` 返回本次版本号和本次 Git 提交短哈希。
- 服务器本机 `/healthz`、`/readyz` 均返回成功，公网 `/healthz` 返回 200。
- 后台首页返回 200，静态文件中不存在 `localhost` 或 `127.0.0.1` API 地址。
- 小程序 `dist/project.config.json` 使用目标 AppID，生产包中不存在本地 API 地址。
- 真实微信登录保持开启，`ALLOW_MOCK_WECHAT_LOGIN=false`。
- 用户的四个未提交文件与 `artifacts/` 在发布后仍保持原状态。
