# UI-20 静态壳路由收口设计

## 目标

在 `master@9c0ca376` 基础上，把已经完成但分散在独立分支的法律条款、搜索页和通用用户主页安全整合进同一个小程序静态壳，并修复当前可确定的坏路由、孤立入口和新版/旧版页面混用问题。

本模块只收口静态页面导航和本地 Mock 展示，不修改后端、API、鉴权、支付、媒体上传、IM 或资金逻辑。

- 工作目录：`C:\Users\33141\Documents\ui20-static-shell-closeout`

## 整合来源

1. `feat/ui-legal@f61a80d4`：法律条款页、路由注册和“我的”入口。
2. `feat/ui-search@db13e36f`：搜索页和首页/二手搜索入口。只引入该提交，不复制其工作树中的误建目录 `apps/miniap/`。
3. `codex/ui-user-profile@97877fe1`：连续七个提交，包含通用用户主页、Mock 数据、路由注册及帖子作者/二手卖家入口。

`feat/ui-static-route-closeout@5b12548b` 已经是 `master` 的祖先，不重复整合。

## 功能范围

### 1. 搜索入口统一

- 首页搜索按钮进入 `/pages/search/index`。
- 二手页搜索框进入 `/pages/search/index`。
- 帖子详情的话题标签进入同一个搜索页，并通过 `keyword` 参数带入标签文本。
- 搜索页保持既有静态设计；本模块不增加真实搜索 API 或结果页。

### 2. 通用用户主页接通

- 帖子作者进入 `/pages/user-profile/index?userId=...&tab=posts`。
- 二手卖家进入 `/pages/user-profile/index?userId=...&tab=secondhand`。
- 二手聊天顶部用户信息进入同一通用主页。
- 未知用户 ID 使用现有通用 Mock 回退，不出现空白页。

### 3. 骑手订单详情坏路由修复

- 骑手配送会话中的“查看订单”不再跳转不存在的 `/pages/delivery-order-detail/index`。
- 复用现有新版配送单详情页，通过 `role=rider` 参数保持骑手会话身份；不复制一套相同详情 UI。
- 商家入口继续使用 `role=merchant`，两种角色返回各自会话和工作台。

### 4. 发布入口统一

- 首页、外卖、二手、我的四个底部中央 `+` 统一进入 `/pages/publish-entry/index`。
- “发帖子”进入新版 `/pages/publish-post/index`。
- “发布配送单”进入新版 `/pages/merchant-publish/index`。
- 当前没有获批的新版“发布二手”视觉稿，因此本模块不得重新暴露旧版 `/pages/publish/index`；该入口显示明确的静态待设计提示，不跳回旧 UI。

### 5. 内容卡片携带稳定 ID

- 首页发现卡片、二手商品卡片和“我的内容”条目均携带稳定 Mock ID。
- 帖子、收藏、评论进入对应帖子详情；评论附带 `anchor=comments`。
- 宝贝进入二手详情。
- 详情页根据 ID 选择对应 Mock 内容；未知 ID 使用现有默认内容，避免白屏。

### 6. 新版路由白名单

- `app.config.ts` 只注册已经完成的新静态 UI 和本次整合页。
- 旧版 `takeout`、`market`、`tools`、`delivery-merchant`、`conversations`、`chat`、`publish`、`media-history`、`takeout-merchant`、`takeout-rider` 等页面源码暂时保留，但从静态壳注册清单移除，防止用户误入旧 UI。
- 不删除旧业务源码；删除或迁移旧实现必须另行授权。
- 全局标题移除“广海空间”旧名称，统一为“湛科生活圈”。

### 7. 底部导航收口

- 新学生壳统一保留：首页、外卖、二手、我的四个入口和中央发布按钮。
- 本模块抽取一个共享的新设计导航组件，替换四个学生主页面中的重复实现。
- 旧五项 `BottomNav` 不再被新版路由使用；旧源码不删除。

## 明确不做

- 不新设计二手发布页、搜索结果页、关于页或工具二级页。
- 不实现真实发帖、图片上传、搜索、IM、电话、退款、钱包、身份资格或数据持久化。
- 不改后端、数据库、迁移、API、services 对外契约和 feature gate。
- 不修改现有页面的视觉布局、颜色、字号和已验收截图结构，除非共享导航替换需要保持像素等价。
- 不合并或清理其它 worktree；验收后由 owner 决定是否删除。

## 失败与回退行为

- 所有 `navigateTo` 目标必须存在并注册。
- 未知内容 ID、用户 ID必须落到现有静态默认数据，不能白屏。
- 未获批页面的入口必须明确提示“静态页待设计”，不得跳到旧版 UI。
- 返回失败时回退到对应角色主页，不跨角色跳转。

## 验收标准

1. `npm run typecheck` 通过。
2. `npm run build:miniapp` 通过，除既有 Sass 和体积告警外无新增错误。
3. `app.config.ts` 中每个注册页均存在，源码内所有静态页面跳转目标均存在并注册。
4. 首页、外卖、二手、我的四个主导航直接互通；中央 `+` 均进入发布选择页。
5. 首页/二手/帖子标签均能进入搜索页。
6. 帖子作者、二手卖家、二手聊天用户均能进入通用用户主页。
7. 商家和骑手配送会话的“查看订单”均能进入配送单详情，且会话角色不串线。
8. “我的内容”四个 Tab 的可点击条目均进入正确详情。
9. 旧版页面不再出现在新版静态壳注册清单中，旧源码无删除。
10. 不提交 `project.config.json` 的 DevTools 自动改动，不带入 `apps/miniap/`，工作树最终干净。

## 设计自检

- 无 `TODO`、`TBD` 或未决范围。
- 未把真实 API 接线混入静态壳收口。
- 未重新启用旧 UI。
- 缺少视觉稿的二手发布页采用明确禁用提示，不自行发明新页面。
- 所有整合来源、角色路由、失败回退和验收条件均有唯一解释。
