# 手势连续性与发布入口自审

基线 `bde6a01`，继续使用 `codex/loading-feedback-polish-20261017`。用户已授权继续自行优化；沿用已批准的细节打磨方向，不新增业务、不改品牌色、咨询页、接口、权限与功能策略，不部署或上传。

## 发现与取舍

1. `createChannelInteraction` 依赖原生抬手/取消事件。横滑中隐藏页面且系统漏发结束事件时，`touching && moved` 可以无限保留；超过 320ms 的常规保护时间仍无法点击。应在页面隐藏/显示、组件卸载时明确结束手势，并拒绝隐藏期回调。重新显示后旧 `change` 事件不能切换栏目，新触摸仍可横滑。
2. 发布选择页的 `navigateTo` 无同步防重入，连点两个入口可能叠加两个编辑页。沿用底部导航的请求身份锁，成功后保留锁至返回本页；失败提示并允许重试，旧请求失败不能解锁新请求。返回使用已有首页兜底方法。
3. 发布卡片没有减少动效样式；后台旧 CSS 层仍把无限旋转缩短到 `.01ms`，由于 `!important` 层优先级可能压过新层。应直接停止循环动画和装饰性按压位移，保留开关位置和静态状态。
4. 帖子检查器未装配首页后来接入的组件，旧静态回归要求首页直接导入 ScrollView。保留真实 ChannelPager 和纯函数；校验 RefreshScrollView 内部使用原生滚动且转发分页/滚动 props，不用空壳绕过行为。

选择局部修复共享交互状态和发布入口。只增加动画无法解决丢失的抬手事件；重做导航会扩大风险且没有必要。保持原生 Swiper 负责拖动距离/速度和 200ms 动画；不改视觉布局，不增加整页入场。

## 验收与自审

- 真实组件回归复现：滑动中隐藏、旧 transition/change 到达、重新显示后的点击与新横滑、卸载后事件；原有滑动防误触与栏目保活仍成立。
- 发布入口验证同帧不同目标连点、失败重试、返回解锁、旧失败不干扰新请求、禁用功能继续不能打开。
- 继续完整前端/项目检查和类型检查；正式小程序构建检查 30 条路由且不含检查页。开发者工具/真机未验证的项目明确保留待验状态。
- 自审：无新依赖、业务接口或资源；测试保留真实组件和断言。临时工程、旧发布产物、原项目均保留。
