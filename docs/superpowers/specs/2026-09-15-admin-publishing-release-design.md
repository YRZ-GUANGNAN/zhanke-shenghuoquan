# 管理员发布首发版设计

日期：2026-09-15。状态：方向已确认，书面设计待用户审阅；尚未实施。

## 目标与约束

交付真实的管理员信息发布版本：普通用户浏览校园信息和使用现有校园服务；不向审核人员展示特殊版本，不按账号、时间、设备或环境偷偷开放社区，不将所有用户授予管理员身份。

公开用户发帖属于后续单独版本：补齐所需资质、如实申报功能并完成相应版本审核后再上线。当前版本不能仅通过远程设置解除发布边界。本文是产品与工程设计，不是通过审核的保证；备案、类目和代码审核需分别核实。

## 方案取舍

1. 采用：真实管理员发布 + 后台显示发布政策并管理真实管理员；首发版锁定普通用户发帖为关闭。可以暂停全部发布，不能在本版本放开普通发布。
2. 后续方案：社区资质与对应版本审核完成后单独发布公开社区版本，再增加正常的运营开关。此项不属于本次实现。
3. 不采用：仅隐藏入口、审核账号区别对待、把所有用户设为管理员、审核后远程偷开。

## 权限与后台设置

- 使用全局政策，不增加按频道配置。
- 后台新增“发布权限”设置区域，显示“当前版本：仅管理员发布”“普通用户发帖：未开放”。
- 设置“管理员发布：开启 / 暂停”，默认开启；仅 active 超级管理员可以变更。普通管理员只读。
- 管理员任命沿用现有用户管理的逐人操作，显示实际管理权限风险并要求确认；不为获得发帖资格自动提升普通用户角色。
- 政策、修改人、修改时间持久化；变更记审计日志，并使用版本号防止并发覆盖。
- 配置缺失使用仅管理员模式；无法可靠读取权限或政策时拒绝写入，不降级为人人可发。
- 服务端每次写入核验当前用户状态与角色，不能依赖前端、缓存角色或用户提交的 role 字段。管理员降权后旧会话不得继续发布。

## 发布与内容可见性

- 小程序沿用现有发帖页面与真实媒体流程，仅有权限的管理员看到入口；发布仍经过现有内容安全与审核流程，不自动批准管理员内容。
- 服务端统一拦截普通用户创建以及所有存在的编辑、恢复、重发路径；旧客户端、直接访问页面、重放请求同样不能绕过。
- 已发表内容新增明确的运营发布标识，仅由服务端在真实管理员发布时写入；不以作者当前角色反向把全部历史内容变成公告。
- 不自动迁移、代发或公开历史用户帖子。首发公开列表、详情、搜索、个人主页、收藏关联和通知关联都只允许公开运营内容；旧用户内容保留于数据库及有权限的后台审核视图。
- 没有运营内容时展示真实空态，不加入测试帖子、生成图片或伪造公告。
- 普通用户公开评论及评论列表在该版关闭，历史评论不删除。公开互动控件、关注流和用户间互动通知不在该版展示。
- 私密意见反馈沿用现有流程，仅本人和授权后台可见；内容举报及已有安全屏蔽能力保留，不把安全功能当成社交入口删除。

## 私信、二手与校园服务边界

- 按前述用户选择，私信、关注、二手整体在该小程序版本中停用，而不只是关闭二手聊天；覆盖首页混合流、发布入口、导航、个人页、搜索、详情跳转和旧分享入口。
- 相关用户 API 与 IM 取令牌/写入授权需要真实执行同一限制；现有聊天长连接及已签发票据是否仍能写入，列为上线前必须验证项，不能只停止前端初始化。
- 保留历史数据、后端模块和订单数据；不执行批量删除。
- 校园工具、跑腿和已有订单流程不做无关改造。订单履约消息与开放私信区分：维持已有参与者鉴权、不扩展交友能力；若关闭共用 IM 会影响履约，则先报告影响，不暗中保留泛用聊天通道，也不直接破坏订单流程。
- 外卖入口及其已有未提交修改不在本文中擅自删除；缺乏真实运营内容的问题作为独立提审检查项，如实报告。

## 组件与接口边界

- 后端集中封装发布政策和读取过滤规则，社区服务与鉴权入口共同使用，避免每页各写一套开关。
- 新增管理政策读写接口与用户能力只读接口，遵循现有响应格式和 CSRF；能力响应不泄露后台管理信息。
- 小程序根据能力响应显示入口；无权限、加载失败、保存冲突都有明确提示，不出现可点但无效的发布按钮。
- 不在前端打包后端密钥；不改变现有管理员登录、学生/骑手/商家身份切换契约。
- 页面与实际行为同步调整文案；不声称已获校园官方授权或已经取得平台资质。

## 验证与发布

1. 后端测试：匿名、普通用户、禁言/封禁用户、管理员、超级管理员；发帖与评论的所有写路径、重放、降权旧会话、政策暂停和配置失败。
2. 后台测试：普通管理员不能改政策或任命管理员；超级管理员成功/失败反馈、并发冲突、审计与 CSRF。
3. 内容测试：历史 UGC 在列表、详情、搜索、个人主页、收藏、通知和深链接均不公开；运营内容仍须审核通过；不丢失旧数据。
4. 小程序测试：无私信/关注/二手可达入口，旧页面直接访问也不能写；保留服务和订单流程回归；IM 票据及长连接单列验证。
5. 类型检查、管理端/小程序构建、相关静态契约检查；不为绿灯删掉有价值的测试，确需调整旧功能断言时逐条说明。
6. 数据迁移只在独立测试数据库演练，不使用生产数据做写入测试。部署、数据迁移及提审不在本轮设计工作中执行。
7. 后续提交说明如实描述运营发布、私密反馈、关闭功能及保留的订单沟通；平台状态和真机结果未验证前不称为可上线。
