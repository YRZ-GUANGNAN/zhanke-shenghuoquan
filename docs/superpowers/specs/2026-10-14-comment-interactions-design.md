# 社区楼内回复、评论点赞与帖子点赞校准

## 范围与依据

用户在全页面版本上传后追加实现评论下继续评论、评论点赞、帖子点赞检查。按其持续有效的全自动实施授权推进，保留蓝色、真实接口、身份和审核、现有开关、咨询例外；当前开发版 `2026.10.14.2` 的源码快照保持可恢复。

参考库基线 `f754573`，已阅读第三轮评论布局正文与 `comment-layout-rules.json`、第五轮长评论状态、机制报告的当前快照/后续变化机制以及 `M58-comment-like-bind.java.txt`。可借鉴回复归属、主次层级、独立点赞列、按稳定 ID 管理状态。500ms 点击绑定只是一条静态调用，不宣称已恢复参考产品完整节流/回滚/服务端实现。实现协议自主设计。

## 选择

采用“一级评论 + 楼内分页回复”，回复二级评论仍归入同一楼，显示直接回复对象。不做无限缩进；不把未加载回复一次性全部返回。保留全文，不新增根据参考单条样本推测的折叠阈值。纯前端模拟不能满足保存、审核和重进后的可靠状态，故采用最小增量后端。

本轮只新增社区评论能力。二手现有回复继续回归，不给二手新增与需求无关的交易/社交功能；不加直播、视频、图片评论、消息推送入口或生产测试内容。

## 数据与兼容

- comments 增加根评论、直接回复评论、直接回复作者、点赞计数；老数据均为根评论。独立 comment_likes 复合主键确保一人一赞。
- 新增受认证的评论线程/回复读取、回复创建、评论点赞目标状态接口；旧根评论创建、列表和帖子点赞路径保持可用。旧列表只展示根评论，防止旧客户端将回复错当新根评论。
- 服务端从路径目标推导 post/root/replyToUser，客户端只提交内容和幂等键。跨帖目标、待审核/下架目标不可回复；回复须过原文本安全检查与审核 outbox。
- 一级与回复分页均有稳定顺序、上限。可见性为审核通过，或仅作者可见自己的待审核/被拒内容；下架的楼和下架的帖子不能通过子接口暴露。
- 评论点赞使用 PUT/DELETE 目标状态，事务内更新关系与计数，服务端回传 liked/likedCount。帖子点赞沿用幂等接口并增加服务端计数回读，不根据未知状态或盲目本地 ±1 决定结果。
- 评论/回复遵循 forum/comment 与 posting_mode；点赞同时遵循 likes；不修改策略配置、用户角色或管理员权限。

## 交互与布局

- 头像、作者、全文、时间与回复入口有清楚归属；点赞独立右列，至少44×44逻辑px触控，窄屏正文可换行。
- “查看 N 条回复”触发真实分页；追加失败保留已有内容和重试入口，展开状态独立于正文、输入草稿和点赞。
- 点击回复进入同一个输入栏，显示回复目标与取消入口；发送失败保留文字与目标，网络失败重试复用同一个幂等键，切目标/内容后更换。
- 每条评论点赞独立 pending，互不锁整页；连续点击不并发重复发请求。确认后更新服务端状态，失败保留先前确认状态；未知状态需重读。
- 待审核评论显示状态，不提前增加公开帖子评论数。切换帖子、离页或账号变化使旧回调失效。
- 动效只服务按压和确认反馈，复用现有图标与蓝色；页面重建/数据回填不误播点赞动画。无高成本或全页持续动画。

## 验证与交付

后端单测覆盖目标归属、审核可见性、幂等冲突、feature guard；隔离MySQL验证迁移、并发点赞唯一性/计数、审核转换、回复分页与目标失效。前端验证请求回执、失败/重试/切目标、页码合并、旧响应隔离、320/390/430和大字号模型布局；二手原回复回归。

完整 verify 与正式构建通过后保存Git。新的后端能力先在隔离环境验证；线上迁移/部署须按既有备份和回滚规范执行，不将已上传旧包说成已包含新增能力。发布审核由用户处理。机型实测与数据接口测试分别报告。

自审：不存在无限嵌套、虚构计数、绕过审核或私自开放模块的依赖；未知的第三方行为未冒充既定需求；新接口使用现有认证和业务开关，旧接口兼容独立验证。
