# 商家与骑手工作区整体改版

用户已在审查汇报后明确授权「往大的方向做」「在不影响目前修改的学生端的前提下去试试」。本次在独立工作树和分支实施，起点为已提交版本 `ab08e57996a0cb36e1aa62462e4a0c0d60b0dad5`。学生端正在进行的动态媒体改动不复制、不修改、不合并。

## 设计决定

采用完整工作区重排：商家以订单处理为中心，骑手以当前履约任务为中心。相较只改变颜色间距，这一方案重新分配头部、状态栏、卡片、次要入口与底部动作。新增经营看板、地图、平台自动接单等业务需要新合同，不纳入此次可独立预览的改版。沿用现有蓝色品牌、真实数据与角色权限。

参考库本地与远端已核对为 `30a9622`。主要依据为商家经营首页逐节点研究、骑手待抢/待取/待送卡片、状态区块矩阵、合单空态与图标资料。借鉴内容顺序、密度、分区、当前动作和状态恢复；所有尺寸重新适配 Taro，不复制第三方表达式、图片或接口。

## 页面组织

1. 商家订单首页：紧凑店铺身份栏、真实订单摘要、独立发单入口、固定阶段栏、双列订单队列。钱包与账单归于既有「我的」资金区，消息使用既有底栏。分组名称改成「待处理 / 配送中 / 已结束」，匹配后台 pending/completed 包含支付失败和取消的真实语义。卡片突出平台与取餐号，地址摘要紧凑，费用和操作固定在卡片底部。
2. 骑手：把接单大厅与在途任务作为两个视图。大厅聚焦可接订单；配送视图只显示待取货与待送达两个阶段。底栏仍使用现有路由和事件；每张卡突出当前目的地，号码、来源、费用构成紧凑识别区，联系和释放为次要动作，当前履约为唯一主动作。
3. 商家详情：状态与取餐号成为首屏摘要；取送路线、履约进度、费用和凭证采用一致分区，保留完整地址及真实时间。联系骑手继续固定于底部，私密凭证沿用短期授权解析与迟到请求保护。
4. 商家发单：重新排列来源与取餐号、导入、取货/收货信息及底部确认区。保留手工发单、平台未接入状态、剪贴板确认、原幂等尝试、付款和结果恢复。
5. 角色「我的」及底栏：角色资料、资金入口与身份切换形成稳定的配套工作区。全部为商家/骑手专属组件，不改变学生底栏与共享样式。

依赖在新工作树单独安装，构建产物仅写该工作树；预览使用独立目录、端口及隔离数据，不连接生产、不发送消息、不产生订单。原工作树中的未提交学生端改动继续由原任务完成。

## 状态与验收

保留资格核验、账号隔离、分页防重、真实数量、原状态机、CAS、幂等键、结果未知禁止重复提交、上传/审核/履约分层和隐藏/卸载清理。新视图切换只能切换已有列表，不对未加载的分页结果作伪造总量。

运行配送工作台、发布、工作区行为回归；更新仅与旧版布局绑定的静态检查，保留其权限/服务/分页断言。新增接单/履约视图和分组语义的回归。运行类型检查、相关合同检查、小程序构建、范围检查，并生成 320/390/430 宽度的实际组件截图，覆盖长编号、长地址、空态和失败状态。全仓原有 external_intake 数据库分层失败单独记录；本次不改后端来修复该问题。

## 自审

所有页面均可使用已有数据独立落地；没有虚构经营数字、距离、超时或平台连接。提取的样式只被角色页面引用。此次授权是隔离试做和预览，未包含发布、部署或合并学生端工作。
