# 微信胶囊独占行统一布局设计

## 目标

所有使用 `navigationStyle: 'custom'` 的 MiniApp 页面，都把微信官方胶囊所在区域视为独立的系统行。业务标题、返回、保存、发布、搜索、更多、身份切换等控件必须从胶囊行下方开始，不得再与胶囊同行或仅通过向左挤压规避重叠。

采用微信原生导航的页面继续由微信管理，无需额外添加占位行。

## 已确认的设计决定

1. 胶囊独占从屏幕顶部到胶囊底部安全间距结束的一整行。
2. 所有业务导航单独占下一行，使用完整页面宽度。
3. 页面允许整体向下移动，以换取统一、易点击和跨机型稳定的顶部结构。
4. 现有颜色、字体、卡片、底部导航和业务流程保持不变，本次只统一顶部布局。
5. 工具目录为空的问题不属于本设计范围，继续保持真实数据为空时不展示虚拟工具。

## 方案取舍

### 采用：胶囊行与业务导航行完全分离

- 优点：标题可以真正居中，左右操作按钮都有完整点击空间，不受不同手机胶囊宽度影响。
- 优点：Android、iPhone、刘海屏和灵动岛机型共享同一规则。
- 优点：页面整体下移后利用当前底部留白，不需要压缩正文或缩小控件。
- 代价：首屏可视内容减少约一行高度，但换来一致性和可用性。

### 不采用：业务按钮继续放在胶囊左侧

虽然改动较小，但会导致标题偏移、搜索框变窄、按钮距离不一致，并在窄屏设备上显得拥挤。

### 不采用：全部恢复微信原生导航

原生导航兼容性高，但无法承载现有的保存、发布、标签、搜索和品牌化头部结构，会破坏当前页面信息架构。

## 几何规则

### 胶囊系统行

运行时读取 `Taro.getWindowInfo()` 与 `Taro.getMenuButtonBoundingClientRect()`。

- 系统行顶部固定为屏幕顶部 `0`。
- 系统行底部为 `max(menu.bottom + 8px, statusBarHeight + 52px)`。
- 系统行内不渲染任何业务可点击控件。
- 背景色或品牌渐变可以延伸到系统行，但只能作为视觉背景。

当胶囊信息不可用时，使用 `statusBarHeight + 52px`；状态栏信息也不可用时，使用 `72px`。回退仅影响高度，不改变页面功能。

### 业务导航行

- 从系统行底部开始。
- 标准高度为 `48px`。
- 左右水平内边距为 `16px`。
- 左侧、右侧操作的最小点击区域均为 `44px × 44px`。
- 页面标题按整个屏幕宽度视觉居中，不按剩余空间居中。
- 右侧文字按钮保持现有品牌色；禁用和加载状态保持现有语义。
- 导航行下方可按现有页面需要保留分割线或阴影。

### 页面正文

- 普通页面正文从“系统行 + 业务导航行”之后开始。
- 首页、搜索、二手和外卖页面的标签、搜索框放入业务导航行或其下方内容行，不再进入胶囊系统行。
- 个人页、公开主页、商家页和钱包页允许背景延伸到屏幕顶部，但头像、名称、编辑、更多和身份切换等交互内容必须位于系统行下方。
- 聊天页、详情页和发布页的返回、标题、主页、保存、发布等操作统一进入业务导航行。
- 底部导航与 `env(safe-area-inset-bottom)` 规则保持不变。

## 组件边界

### `capsule-safe` 几何模块

保留纯计算职责，输出：

- `systemRowHeight`
- `businessRowTop`
- `businessRowHeight`
- `totalHeaderHeight`

模块不关心标题文本、颜色或页面业务，也不直接执行导航。

### `CapsulePageHeader`

负责标准页面顶部结构：

1. 渲染独立胶囊系统行占位。
2. 渲染下一行的左操作、居中标题和右操作。
3. 提供 `standard`、`search`、`tabs` 三种内容布局，但共享相同系统行。
4. 页面只传文本、图标、状态和事件，不再自行计算胶囊右侧距离。

### 品牌头部页面

个人、商家等渐变头部继续使用自己的视觉容器，但复用同一系统行高度。业务内容区域以 `businessRowTop` 为最小起点，禁止在各页面重新写固定的 `84rpx`、`96rpx` 或 `112rpx` 顶部避让值。

## 页面覆盖范围

覆盖 `apps/miniapp/src/pages` 下所有声明 `navigationStyle: 'custom'` 的页面，包括：

- 首页、搜索、二手、外卖等学生主页面；
- 编辑资料、设置、关于、法律条款、黑名单、意见反馈；
- 发布入口、发布帖子、发布二手；
- 帖子详情、二手详情、二手私聊、用户主页、我的内容；
- 身份申请；
- 商家首页、商家消息、商家发布、商家订单详情、商家钱包；
- 骑手钱包及后续新增的自定义导航页面。

新增自定义导航页面必须使用统一组件或统一几何模块，不允许复制固定顶部间距。

## 状态与错误处理

- 胶囊 API 调用失败时使用统一回退高度，不能让页面白屏。
- 保存、发布等业务错误仍由现有 Toast 和页面状态处理，布局组件不吞掉业务错误。
- 屏幕重新显示时可重新读取一次窗口与胶囊信息，避免开发者工具切换机型后保留旧值。
- 点击区域不得进入微信胶囊矩形，也不得被透明标题层覆盖。

## 验证方案

### 自动验证

- 为纯几何函数覆盖 320px、375px、393px、430px 宽度及 API 失败回退。
- 断言业务导航顶部严格大于胶囊底部。
- 断言系统行内没有业务点击控件。
- 运行 MiniApp `typecheck`。
- 使用公网 API 地址完成 WeChat 构建，并确认产物不包含 `127.0.0.1`。

### 页面回归

- 标准页：编辑资料的“取消 / 标题 / 保存”。
- 发布页：发布帖子的“取消 / 标题 / 发布”。
- 搜索页：返回、输入框和搜索按钮。
- 首页：私信、发现、工具标签与搜索入口。
- 聊天页：返回、用户信息和主页按钮。
- 品牌头部：个人资料、公开主页、商家身份切换。

### 真机验收

- 至少一台 Android 和一台 iPhone；若暂时只有一台设备，另一平台明确保留为 `PENDING`。
- 验证所有顶部按钮可见、可点击、标题居中、胶囊行无业务控件。
- 资料保存、发布入口、搜索和身份切换至少各完成一次真实点击。
- 真机验收通过前不上传体验版或提交发布。

## 完成标准

1. 所有自定义导航页面都有独立胶囊系统行。
2. 所有业务控件位于下一行或更低位置。
3. 不再存在按页面手写胶囊右侧避让的布局。
4. 页面整体下移后无正文遮挡、无底部导航覆盖、无新增横向溢出。
5. 自动检查、构建和当前可用真机验证通过；不可用平台保持诚实的 `PENDING`。
