# 小程序功能可见性中心设计

日期：2026-09-15。状态：用户已选择方案 A，书面设计待审阅；尚未实施。

## 目标

在后台管理网站提供统一的“功能可见性中心”，让管理员按功能开启或关闭小程序入口与对应写入能力。开关作用于当前本地作业环境，不改变用户角色，不授予后台权限，不删除数据，不连接生产环境。

## 开关清单

以下功能独立保存、独立生效：

| key | 功能 | 关闭后的用户行为 |
| --- | --- | --- |
| forum | 论坛浏览 | 隐藏论坛内容、搜索范围和相关详情入口；旧链接返回“暂未开放” |
| post | 发帖 | 隐藏发布帖子入口；直接创建请求由后端拒绝 |
| comment | 评论 | 隐藏评论输入与互动入口；直接评论请求由后端拒绝 |
| secondhand | 二手市场 | 隐藏二手导航、首页商品、搜索、详情和发布入口；旧链接提示暂未开放 |
| secondhand_publish | 商品发布 | 保留二手浏览（若开启），但不能新增商品 |
| secondhand_chat | 二手聊天 | 隐藏聊天入口并拒绝新会话写入；不删除历史消息 |
| takeout | 外卖商家目录 | 隐藏商家目录、商家搜索和新点餐入口；不影响校园工具 |
| campus_tools | 校园服务工具 | 隐藏工具入口；已有订单、账号和基础支持不受影响 |
| delivery | 跑腿服务 | 隐藏新订单入口；已有订单查询、取消、退款、售后按原状态机继续 |
| merchant | 商家工作台 | 隐藏商家身份入口和新业务写入口；已有订单处理按履约权限保留 |
| rider | 骑手工作台 | 隐藏骑手入口和新接单入口；已有订单按履约权限保留 |
| messages | 通用私信 | 隐藏私信入口并拒绝新私信写入；订单必要沟通单独按参与方鉴权 |
| following | 关注关系 | 隐藏关注入口并拒绝新增/删除关系；历史关系保留 |

“论坛”和“发帖/评论”分开：论坛可只读开启、写入关闭。二手市场和二手发布/聊天也分开。三个功能关闭时，首页保留仍开启的真实服务与个人入口，不加入测试内容或装饰数据。

不可关闭的基础能力：登录/退出、账号注销、隐私政策与用户协议、意见反馈、举报、审核后台、订单查询和已开始订单的必要履约操作。后台本身的认证、CSRF、审计和超级管理员保护不可被配置隐藏。

## 默认值与安全策略

- 首次初始化默认保持当前功能可见性，避免意外破坏现有作业演示；`post`、`comment` 默认跟随此前确认的“仅管理员”模式，而不是自动开放全员。
- 配置缺失、版本不兼容、读取失败或缓存过期时，用户端不展示对应可选模块；后端拒绝该模块的新写入。不能以失败为理由默认放开功能。
- 后台开关必须显式启用本地实验配置并使用独立测试数据库。生产构建不注册实验写接口；不能按审核账号、时间、设备或来源自动切换。
- 切换只影响新入口与新写入。正在进行的订单事务不被中断，历史内容、商品、关系和消息不删除。

## 后台操作

- 新增“功能设置”页面，按“社区、交易与服务、身份工作台、交流关系”分组展示开关。
- 每项显示状态、影响说明、最近修改人和时间；论坛下方显示“发帖与评论模式：仅管理员／全部用户”的现有实验设置。
- 只有 active 超级管理员可以修改；普通管理员只读。保存使用既有管理员会话、CSRF 和响应格式。
- 每次保存带版本号，发生并发冲突时拒绝覆盖并要求刷新；操作记录写入审计日志。
- 开关之间只允许声明依赖，不隐式级联：关闭 `forum` 时自动阻止 `post`、`comment` 的用户入口，但保存的子开关值保留；重新开启论坛后恢复原先子开关状态。关闭 `secondhand` 同理不删除 `secondhand_publish`、`secondhand_chat` 的保存值。
- 后台明确区分“入口隐藏”和“服务停用”：对有写接口的功能两者同时执行；只读模块可仅隐藏入口但服务端仍按模块状态保护详情和搜索。

## 服务端架构

- 在配置/设置领域增加模块政策仓储、版本号和审计记录；通过一个服务提供 `GetFeaturePolicy`、`UpdateFeaturePolicy`、`CanUseFeature` 等能力。
- 管理端增加 GET/PATCH `/admin/feature-policy`（具体路径遵循现有 API 命名），PATCH 只接受白名单 key、布尔值和期望版本号，拒绝未知字段。
- 用户端增加只读能力接口，返回可见模块与当前用户的 `canPost`、`canComment` 等能力；不泄漏后台会话或其他用户信息。
- 所有受影响的写入口都在后端统一检查：社区 CreatePost/CreatePostKeyed、AddComment/AddCommentKeyed；交易创建/聊天；IM 私信；关注关系；外卖和跑腿新订单；商家/骑手工作台的新业务操作。直接请求、旧客户端和幂等重放不能绕过。
- 订单读取、已开始事务和必要履约沟通使用独立的订单参与方鉴权，不因通用模块开关中断；若现有 IM 通道无法区分两者，先阻止关闭并返回清晰错误，不暗中保留泛用私信。
- 关闭模块返回稳定的 403/业务错误码和中文提示；匿名仍返回 401，禁言/封禁继续使用既有状态码。配置读失败使用拒绝写策略。

## 小程序接入

- 在应用启动和 `useDidShow` 时刷新能力；首页、搜索、发布入口、底部导航、个人页、二手、校园服务和工作台按能力渲染。
- 关闭功能的页面被直接打开时显示统一空态/返回按钮，不能白屏、无限跳转或初始化真实业务写请求。
- 发布页在显示前检查 `post`/`secondhand_publish`；帖子详情在加载评论前检查 `forum`/`comment`；外卖页只移除商家区，保留校园工具区。
- 搜索请求按能力裁剪 scope；首页不混入已关闭频道；分享卡片和通知深链同样经过服务端能力校验。
- 保留现有真实数据、内容安全、身份守卫、支付和订单接口契约；只增加能力字段和受限状态处理。

## 验证矩阵

1. 逐项开关：每个功能开启/关闭、刷新、重启后持久化；未知 key、版本冲突、数据库错误和权限不足。
2. 组合验证：论坛×发帖×评论、二手×发布×聊天、外卖×校园工具、跑腿×订单、商家×骑手；至少覆盖全部关闭、全部开启和互相独立的混合状态。
3. 身份验证：匿名、普通用户、禁言、封禁、管理员、超级管理员；用户 role 在切换前后保持不变，普通用户不能进入后台。
4. 旁路验证：旧页面 URL、分享深链、旧客户端请求、直接 API、幂等重放、缓存旧能力、降权旧会话。
5. 业务回归：历史内容/商品/消息不删除；订单查询、履约、取消、退款、售后继续可用；关闭外卖不影响校园工具。
6. 工具验证：后端测试、admin/miniapp typecheck、构建和现有静态契约检查；提供本地后台截图/预览与测试记录。
