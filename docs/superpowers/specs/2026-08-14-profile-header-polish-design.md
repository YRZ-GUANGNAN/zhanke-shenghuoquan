# “我的”页资料头部细节优化设计

## 目标

在保留真实头像、昵称、身份、用户号、学校信息和“编辑资料”入口的前提下，优化“我的”页顶部资料区的比例与信息层级，并移除容易被误解为在线状态的绿色圆点。

## 现状判断

- 绿色圆点没有独立业务状态含义，却与“学校未设置”并列，容易被理解为在线、认证或连接状态。
- 头像、姓名、身份标签和右侧编辑按钮同时强调，信息重心略分散。
- 学校信息字号与间距偏小，三行文字之间的节奏不够稳定。
- 当前头像、编辑资料、胶囊安全区和资料接口均已打通，不应改动数据与导航逻辑。

## 方案对比

### 方案 A：中性元信息（采用）

移除绿色圆点，仅保留学校或校区文字；通过文字颜色和固定行高表达次级信息。头像适度收紧，姓名与身份标签保持同一基线，编辑入口使用低强调的浅色按钮。

优点：信息真实、层级清楚、无额外视觉噪声，也不会误导用户。

### 方案 B：学校图标前缀

用学校图标替代绿色圆点。

缺点：会额外占用横向空间，在学校与校区名称较长时更容易挤压；图标本身也没有新增信息价值。

### 方案 C：未设置时隐藏学校行

学校为空时只显示用户号。

缺点：虽然更简洁，但会隐藏可操作状态，降低用户进入编辑资料完善信息的动机。

## 最终设计

- 保留白底、胶囊安全区和整块可进入编辑资料的交互。
- 头像缩为更协调的圆形尺寸，继续使用真实 `profile.avatar`，无头像时保留首字占位。
- 姓名使用主标题层级；身份标签缩小并降低填充强度，避免与姓名争抢视觉重心。
- 用户号与学校信息形成稳定的两行辅助文本；学校行不再包含圆点、光晕或状态色。
- “编辑资料”使用轻边框、浅背景和箭头，维持足够触控面积，但视觉权重低于用户信息。
- 长昵称、长学校名继续使用单行省略，防止窄屏挤压或按钮换行。
- 不新增图片、假数据、接口、路由或依赖，不改变头像上传与身份切换逻辑。

## 验证

- 静态契约确认头像真实数据、`aspectFill`、学校状态文字与编辑资料路由仍保留，同时禁止绿色圆点类回归。
- 运行资料中心专项检查、头像链路检查、小程序 TypeScript 检查和本地小程序构建。
- 检查构建产物不再包含 `student-profile-user__campus-dot`。
- 最终由用户在微信开发者工具及真机审查视觉比例；本轮不上传微信版本。
