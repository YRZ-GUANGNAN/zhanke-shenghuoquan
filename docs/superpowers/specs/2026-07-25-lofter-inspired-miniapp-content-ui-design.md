# 小程序内容优先信息流 UI 设计

## 背景

当前小程序已经具备帖子、二手、外卖、私信、发布、个人资料、身份审核、商家工作台和骑手工作台等真实业务能力，但视觉层存在以下问题：

- 学生端首页虽然已经使用双列瀑布流，卡片仍以厚阴影、大圆角和大面积浅蓝背景为主，图片、标题、作者和互动信息之间的层级不够明确。
- 首页搜索仅表现为标题栏右侧的小图标，无法像内容平台一样清楚表达“可以搜索什么”。
- 搜索、列表、详情、个人页和发布页使用的间距、圆角、背景与信息密度不一致，页面之间存在明显割裂。
- 部分页面将装饰性渐变、空白和大卡片放在真实内容之前，导致首屏有效信息偏少。
- 商家端和骑手端已经形成各自的真实业务工作台，不适合直接改造成内容瀑布流，但需要与学生端共享更清晰的字体、颜色、卡片和图标规则。

用户提供的参考方向是网易 LOFTER 一类的内容优先信息流。项目只借鉴其信息密度、双列瀑布流、搜索框层级、图片优先和文章式详情结构，不复制其品牌标识、专属图标、广告、文案或其他受保护的视觉资产。

## 已确认方案

采用方案 A：

- 学生端内容区域完整采用内容优先、轻量编辑式视觉语言。
- 商家端和骑手端保留原工作台结构，只统一视觉规则，不改造成瀑布流。
- 保留全部现有功能、路由、接口、审核、权限、身份切换和状态机。
- 首页搜索下方不放广告，不保留广告空位，内容流直接承接搜索区。
- 本次 UI 改动独立提交，不混入现有未提交业务、环境或部署文件；若验收不满意，可以整体回退。

## 目标

### 内容目标

- 首屏优先显示真实帖子、二手商品和用户生成内容。
- 图片内容以图片为第一视觉层，文字内容仍可作为独立卡片自然进入瀑布流。
- 用户能快速识别内容类型、标题、话题、作者、互动数和二手价格。
- 搜索入口在页面中可见、可理解，同时继续遵守帖子、二手、外卖的领域边界。

### 视觉目标

- 使用白色内容面、深墨色正文、中性灰辅助信息和低饱和校园青蓝强调色。
- 减少大面积蓝色渐变、厚阴影、发光和过度圆角。
- 提高文字与图标清晰度，统一尺寸、线宽、基线和点击区域。
- 保持微信官方胶囊独占安全行，任何自定义按钮不得与胶囊重叠。

### 工程目标

- 不新增后端接口，不修改数据库，不改变请求参数和响应契约。
- 不新增广告模块、远程图标库或不必要的运行时依赖。
- 尽量通过共享设计令牌、共享导航和现有组件实现一致性，避免每页复制一套样式。
- 加载、空数据、错误、局部失败和重试状态继续明确区分。

## 非目标

- 不复制 LOFTER 的品牌 Logo、广告位、品牌专属图形或原始页面素材。
- 不把商家、骑手的订单工作台改造成社交内容流。
- 不合并帖子、二手和外卖的搜索接口或热词数据。
- 不改变身份审核门禁、支付开关、订单状态机、私信关系或发布审核流程。
- 不新增虚拟用户、虚拟余额、虚拟订单、虚拟热度或演示广告。
- 不处理与本次 UI 无关的环境、部署、服务器或支付配置。

## 视觉系统

### 色彩

- 页面主背景：接近白色的中性灰，用于区分页面和内容面，不使用明显蓝灰蒙层。
- 内容面：纯白或极浅灰白。
- 主文字：深墨色，承担标题、正文和重要数字。
- 次文字：中性灰，承担作者、时间、状态说明和计数。
- 强调色：保留校园青蓝，用于选中状态、链接、主要按钮和少量标签。
- 互动色：点赞使用克制的暖粉红；价格、警告、成功和错误继续使用各自语义色。
- 商家和骑手端可保留身份识别蓝色，但降低渐变和装饰面积。

### 字体层级

- 页面主标题、内容标题和关键数字使用清晰的中高字重。
- 正文保持舒适行高，不使用过浅颜色。
- 辅助文字、标签、时间和统计数字降低字号和对比度，但必须可读。
- 同一信息区不同时使用过多相近字号。
- 数字与单位保持基线对齐。

### 圆角、边框和阴影

- 内容卡片使用中小圆角；图片与卡片轮廓保持一致。
- 以间距和细分隔线建立层级，阴影只作为极轻的辅助。
- 搜索框使用完整胶囊圆角。
- 主操作按钮使用稳定的中等圆角，不使用发光阴影。
- 底部弹层保留较大上圆角，以区分页面与临时操作层。

### 图标

- 继续使用项目内 SVG 或 CSS 线性图标，不使用 Emoji 或单个汉字冒充图标。
- 统一 `viewBox`、描边粗细、端点、尺寸和视觉重心。
- 首页搜索、底部导航、点赞、收藏、评论、分享、更多和返回图标必须清晰可辨。
- 所有核心点击区至少满足约 44px 的可操作尺寸。

## 页面设计

### 1. 学生端首页

页面从上到下分为：

1. 微信胶囊安全行。
2. “私信 / 发现 / 工具”业务标签行。
3. 搜索行。
4. 当前标签的真实内容区。
5. 学生端底部导航。

搜索行规则：

- 使用整行浅灰胶囊搜索框，包含清晰的搜索图标和领域文案。
- 首页“发现”入口以帖子和校园内容为主，点击后进入现有搜索页。
- 搜索框下方直接进入瀑布流，不显示广告、运营横幅或对应空白占位。
- 搜索区与内容流之间只保留正常内容间距。

“发现”信息流规则：

- 继续使用双列瀑布流。
- 图片卡以图片为主，图片下显示标题、话题、作者和点赞。
- 纯文字帖子可以使用浅灰文字卡，避免伪造图片占位。
- 二手卡必须显示价格或二手状态，不能与普通帖子完全同形。
- 图片加载失败时显示克制的内容类型占位，不使用彩色条纹制造虚假素材感。
- 卡片间距紧凑但不拥挤，避免厚阴影形成“悬浮积木”效果。
- 无限加载、部分来源失败和点击重试逻辑保持不变。

“私信”和“工具”规则：

- 私信继续读取真实会话，不新增演示联系人。
- 工具继续读取真实工具配置，不新增虚拟工具。
- 两个标签与“发现”共享字体、列表间距、空状态和错误状态规则，但不强制使用瀑布流。

### 2. 搜索

- 搜索页保留现有领域入口和真实接口。
- 从帖子进入时只搜索帖子、话题和校园动态。
- 从二手进入时只搜索二手商品。
- 从外卖进入时只搜索商家或对应外卖内容。
- 搜索框采用参考图的整行浅灰胶囊结构，返回和提交操作不得挤压输入区。
- 搜索历史、热搜和自定义标签继续显示真实数据，不生成虚假热词。
- 结果列表按领域展示必要信息：
  - 帖子：标题、摘要、话题、作者、发布时间。
  - 二手：图片、标题、价格、分类、校区、状态。
  - 外卖：商家名称、说明、营业状态。
- 空结果、请求失败和返回推荐保持独立状态。

### 3. 帖子详情

- 顶部作者区保留头像、作者、学校、关注和返回。
- 正文区域采用文章式白底阅读结构。
- 图片、标题、正文、话题和发布时间按内容顺序连续排布，减少卡片套卡片。
- 评论区使用头像、昵称、正文、时间、回复和点赞的清晰纵向列表。
- 底部评论输入、点赞、收藏和评论操作继续使用真实行为。
- 底部操作栏包含安全区，不遮挡最后一条评论。

### 4. 二手列表与详情

- 二手列表继续使用领域专属搜索、筛选和商品数据。
- 商品卡以图片和价格为主要视觉层，标题、分类、卖家和收藏为次级信息。
- 二手详情保留大图、价格、状态、描述、标签、卖家、风险提示、收藏和联系卖家。
- 私聊、联系弹层、收藏和卖家主页入口行为不变。
- 风险提示保留语义色，但不使用过大的警告卡片抢占主要内容。

### 5. 发布、私信和个人页

- 发布入口、发帖、发布二手、聊天、会话、个人资料和资料编辑只调整布局与视觉，不删除字段和动作。
- 输入控件统一为轻灰底或细边框，焦点和错误状态清晰。
- 图片上传继续使用现有真实上传流程。
- 个人页保留统计、身份切换、审核入口、设置和资料编辑。
- 已审核与未审核身份继续由真实状态决定，不通过视觉改造绕过门禁。

### 6. 商家端和骑手端

- 保留现有工作台信息架构、审核门禁、订单分组、钱包、消息、电话、凭证和状态操作。
- 保留微信胶囊安全行和身份切换位置。
- 降低大面积高亮渐变、装饰圆和厚阴影。
- 统一主次文字、数字、状态标签、卡片边框、按钮圆角和 SVG 图标。
- 订单、路线、费用和主操作仍是最高优先级，不套用瀑布流。
- 不改变此前已经确认的商家首页清晰化和骑手工作台深度精修业务边界。

## 交互与状态

### 导航

- 学生端底部导航保留首页、外卖、发布、二手、我的五个入口。
- 中央发布按钮保留，视觉从高发光悬浮球收敛为清晰的深色或校园青蓝主按钮。
- 当前页使用清晰的选中颜色和图标状态，未选中项使用中性灰。
- 页面跳转方式和路由保持不变。

### 加载

- 首次加载显示与目标页面结构相符的轻量状态。
- 已有内容时后台刷新不得清空页面或造成整页白屏。
- 图片加载失败不影响标题、价格和作者信息显示。

### 空状态

- 空私信、空帖子、空二手、空订单和空搜索结果使用各自准确文案。
- 空状态不伪造内容、用户、订单或热度。
- 空状态高度随内容收敛，不制造大面积无意义留白。

### 错误与重试

- 网络错误与真实空数据必须区分。
- 部分数据源失败时保留已成功加载的内容。
- 重试入口保持可点击，并避免与微信胶囊或底部安全区冲突。

## 数据与功能保护

以下能力必须保持现状：

- 帖子和二手的分页、详情、点赞、收藏、评论和发布。
- 帖子、二手、外卖分域搜索及其历史、热搜和标签。
- 私信会话、聊天关系和图片发送能力。
- 用户真实资料、真实用户号、资料编辑和身份切换。
- 商家和骑手身份申请、证明图片、后台审核和访问门禁。
- 商家订单、钱包、账单、消息和配送单发布。
- 骑手抢单、取货、配送、送达、电话、消息和凭证上传。
- 支付功能开关及未开通状态。

本次不得新增、删除或修改后端请求。

## 实施顺序

1. 记录基线提交和工作区状态，确认本次范围不覆盖用户已有未提交文件。
2. 收敛全局设计令牌、页面背景、字体和基础控件。
3. 改造首页标签、搜索行、瀑布流卡片和底部导航。

5. 改造帖子、二手列表与详情。
6. 统一发布、私信、个人页的信息样式。
7. 将共享视觉规则安全应用到商家和骑手工作台，必要时做定点修正。
8. 完成静态检查、类型检查、构建和微信开发者工具截图验收。
9. 仅暂存本次 UI 文件，生成一个可整体回退的实施提交。

## 验收标准

### 视觉验收

- 首页胶囊安全行、标签行、搜索行和信息流层级清晰。
- 搜索框下方没有广告、广告占位或异常大间距。
- 双列瀑布流在 iPhone 15 Pro 和较窄屏幕下不重叠、不溢出。
- 图片、标题、作者、标签、互动数和价格之间层级明确。
- 纯文字帖子无需伪造图片即可自然显示。
- 底部导航图标清晰、基线一致，中央发布按钮不过度突出。
- 帖子详情和评论流可连续阅读，底部操作栏不遮挡内容。
- 二手详情的价格、卖家和联系操作清晰。
- 商家和骑手页面仍能一眼识别为工作台，且不出现内容瀑布流。
- 所有页面继续为微信官方胶囊单独让位。

### 功能验收

- 首页三标签、底部五入口和中央发布入口可用。
- 帖子搜索只返回帖子领域结果；二手和外卖搜索保持各自领域。
- 帖子、二手详情和所有真实互动行为可用。
- 私信、图片发送、个人资料编辑和身份切换可用。
- 未审核商家或骑手无法进入对应工作台。
- 已审核商家和骑手的原有订单与工作流可用。
- 不新增任何广告请求或广告占位。

### 自动验证

- 小程序类型检查通过。
- 小程序生产构建通过。
- 胶囊布局静态检查通过。
- 首页真实工具合同检查通过。
- 发布、搜索、身份审核和业务闭环相关静态检查通过。
- 新增必要的 UI 边界检查，至少防止广告占位回归、搜索行消失和搜索领域被合并。

### 手动验证

- 微信开发者工具中依次检查首页、搜索、帖子详情、二手列表、二手详情、发布、私信和个人页。
- 使用真实审核通过的商家与骑手身份检查工作台。
- 检查加载、空数据、失败、部分来源失败和重试状态。
- 在模拟器和真机检查微信胶囊、底部安全区、点击区域、图片比例和字体清晰度。

## 回退策略

- 设计规格单独提交。
- 实施阶段不暂存现有 `.env`、部署、项目私有配置或其他用户未提交文件。
- UI 实施完成并通过验证后，只把本规格列出的 UI 文件加入一个独立提交。
- 若用户不接受最终效果，使用 `git revert <UI 实施提交>` 整体撤回，不影响之前的业务功能和用户已有工作。
- 若某个页面在实施中出现功能回归，先恢复该页面原展示结构，再重新应用共享视觉规则，不用业务逻辑换取视觉统一。
