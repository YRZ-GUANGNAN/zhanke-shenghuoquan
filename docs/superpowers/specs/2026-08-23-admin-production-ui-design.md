# 湛科生活圈后台管理上线级 UI 设计

## 目标

在不修改现有业务能力、权限模型、API 路径、请求参数或响应契约的前提下，把 `apps/admin` 从功能可用的内部页面收敛为可上线审查的运营管理网站。改造覆盖登录、全局壳层、公共组件及全部现有后台模块，不引入虚构数据、趋势图、业务入口或第三方视觉资产。

## 已选方案

采用“全系统收敛”，而不是只美化数据首页，也不重写框架。

- 保留 React、Zustand、Vite、现有服务层与权限判断。
- 用统一设计令牌和公共组件改善所有模块；业务复杂页面只做局部结构整理。
- 登录页、工作台壳层、普通表格页和媒体/配送/导航等专用控制台共享同一视觉语言。
- 真实接口返回什么就展示什么；没有趋势数据时不绘制趋势图，没有内容时使用诚实空态。

未选择的方案：

1. 只优化登录页和数据统计。风险是其余十余个模块仍然割裂，不能达到“后台网站可上线”的目标。
2. 从零重写后台。风险是审核、配送、媒体和导航等复杂流程容易出现回归，也会扩大接口与权限风险。

## 信息架构

保留现有 `AdminSection` 和页面切换逻辑，只重新组织导航的视觉分组：

- 运营中心：媒体运营、配送运营、受功能开关控制的外卖运营。
- 内容治理：统一审核、帖子管理、商品管理、举报审核、身份审核。
- 平台管理：数据统计、用户管理、导航管理。

分组只影响呈现，不改变 section key、feature flag 或路由行为。侧栏固定显示产品名称、环境说明和当前模块；顶栏显示页面标题、简短说明和账户操作。窄屏时侧栏收窄但不隐藏关键入口，内容区允许表格横向滚动。

## 视觉系统

- 背景：冷静的浅灰蓝工作台背景；主要内容使用连续白色或弱分区表面，不堆叠重阴影卡片。
- 文字：深蓝灰主文字、单一品牌蓝强调、绿色/琥珀/红色只用于成功、警告和危险状态。
- 尺寸：8px 基准间距；主要内容最大宽度约 1500px；表格行高 52–60px；控件最小高度 40px；高风险操作保留明确二次确认。
- 字体：使用系统中文字体栈，数据使用 tabular numbers；标题、说明、表格元数据形成四级层级。
- 圆角：控件 8–10px、容器 12–16px、弹窗 16–20px；不对所有内容使用胶囊。
- 反馈：所有按钮、侧栏入口、表格操作有 hover、focus-visible、active 和 disabled 状态；遵守 reduced-motion。

## 全局壳层与公共组件

### 壳层

- 侧栏宽度稳定，导航分组、图标尺寸和 active 状态统一。
- 顶栏保持粘性，使账户和当前模块在长表格滚动时可见。
- 主内容采用统一页头：标题、说明、主要操作、辅助统计或筛选。
- 页面在 1440px、1180px、900px 三档保持可读；数据表不压缩到不可操作。

### 公共组件

继续使用并扩展现有 `AdminButton`、`AdminField`、`AdminSelect`、`AdminBadge`、`AdminNotice`、`AdminState`、`AdminDialog` 和 `AdminIcon`：

- 统一默认尺寸、图标光学大小、边框、焦点环和危险色。
- 加入通用页面标题、工具栏、表格容器和状态映射样式，不创建重复的业务组件。
- loading、empty、error 保持语义一致；错误信息继续显示服务层提供的真实错误。
- 确认、拒绝、下架、改判、删除、修改密码继续使用已有确认流程，不将危险操作变成单击即执行。

## 模块设计

### 登录与账户

登录页以清晰的安全入口为中心，保留独立管理员密码、长度要求、错误信息、busy 状态和自动完成属性。账户区保留修改密码与退出，弹窗提高层级和键盘焦点可见性。

### 数据统计

只显示接口已有的用户、帖子、商品和待审核四项统计。四项使用规则指标带展示总量与“今日”值，不增加趋势、比例或目标值。加载失败、加载中分别使用统一状态组件。

### 用户与内容治理

- 用户：按用户身份信息、当前状态、状态操作和仅超管角色操作分区；危险操作降低误触概率。
- 统一审核：保留筛选、分页、任务选择、开始审核、通过、拒绝和改判；列表与详情形成主从层级。
- 帖子、商品、举报：保留真实字段和现有下架/跳转审核能力；状态统一翻译为中文语义徽标。
- 身份审核：保持现有申请详情和审批逻辑，统一到相同页面标题、工具栏、详情和反馈系统。

### 专用运营控制台

- 媒体运营：保留现有素材、任务和错误信息，统一容器、筛选、状态与操作层级。
- 配送运营：保留订单、费用、资金、补偿和会话等现有能力，优先保证大表格、长编号和金额可扫读。
- 外卖运营：继续受 `legacyTakeoutEnabled` 控制，不绕过功能开关。
- 导航管理：合作商家目录和普通导航入口继续分开；保留 `external_takeout_merchants` 的系统域边界、营业状态、可见性和 AppID/Path 管理。

## 数据流和接口边界

- `adminAPI`、`adminAuthAPI`、配送、媒体、外卖和导航服务函数保持签名不变。
- 不把 `external_takeout_merchants` 与普通导航项合并；系统分类继续在服务层按 `systemKey` 区分。
- 写请求不增加自动重试；错误继续通过现有错误类型进入 UI。
- 权限仍由管理员会话、`AdminRequired`、`SuperAdminRequired` 和各业务端点控制；前端只反映权限，不模拟权限。
- 不接入 mock、fixture、生成图片或虚构统计到正式后台。

## 可访问性与操作安全

- 交互控件最小目标 40px，核心或危险操作建议 44px。
- 所有键盘可操作元素保留清晰 `focus-visible`；非按钮交互不新增无语义容器。
- 表格保留标题和列头；滚动容器不吞掉键盘焦点。
- 状态不只依赖颜色，同时使用文本；错误使用 `role="alert"`，异步成功或刷新使用 `role="status"`。
- 弹窗保留明确标题、说明、取消和确认；不改变现有密码、拒绝原因和下架原因的校验。

## 验证与验收

必须完成：

1. `npm --workspace apps/admin run typecheck`。
2. `npm --workspace apps/admin run build`。
3. 与后台相关的现有静态契约检查；只记录无关基线失败，不扩展修复范围。
4. 登录页真实构建预览。
5. 有管理员会话时检查数据统计、统一审核、用户管理、配送运营和导航管理；没有会话时使用不接入正式代码的静态空态预览，并明确真实数据验收待用户登录。
6. 1440px、1180px、900px 三档布局检查；验证长文本、长编号、金额、空态、错误态和表格横向滚动。

## 非目标

- 不新增后端接口、数据库字段、管理员角色、审计策略或业务统计。
- 不修改小程序页面、学生端底栏、校园服务接口或正在进行的后端改动。
- 不引入图表库、UI 框架、外部字体、第三方图片或生成式图片。
- 不执行上传、部署、合并或生产数据操作。
