# 商家端与骑手端工作台整体升级设计

## 目标

在不改变身份审核、订单状态机、钱包开关、消息路由和服务端数据合同的前提下，把商家端与骑手端升级为一套成熟、清晰、适合高频操作的角色工作台。改造覆盖角色首页和关键二级页面，所有内容继续来自真实接口；无数据时使用真实空状态，不补造订单、金额、评价或商家信息。

## 方案选择

### 方案 A：只调整颜色和圆角

风险最低，但无法解决当前 Hero 过重、指标与操作混杂、订单卡层级不稳定、二级页面风格分裂的问题，不采用。

### 方案 B：统一工作台框架，保留角色差异

建立共享的角色工作台视觉语法：胶囊安全区、身份摘要、核心指标、快捷操作、分段标签、订单卡和页面状态保持一致；商家端强调“发布与跟单”，骑手端强调“抢单与履约”。业务组件和路由不重写，只重排层级并收敛样式。该方案改善明显、回归面可控，作为实施方案。

### 方案 C：重做导航与业务结构

会改变用户已有路径，也容易复现已放弃的宽泛 UI 实验，不采用。

## 视觉系统

- 背景使用冷白灰连续画布，主表面使用白色；去掉大面积高饱和渐变、装饰光球和不必要的多色卡片。
- 唯一品牌主色保持现有蓝色；绿色、橙色、红色只用于成功、进行中、风险等业务状态。
- 页面外层圆角为 24–28rpx，内部控件为 16–20rpx，状态标签为紧凑圆角，不让所有元素都呈胶囊形。
- 数字指标启用等宽数字，标题、正文、辅助文字形成明确的 34/28/24rpx 三级比例。
- 阴影只用于浮层和关键工作卡，列表主要依靠间距与弱分隔线区分。
- 动效限制在按压、标签切换和刷新图标，时长 160–220ms，并兼容减少动态效果设置。

## 工作台结构

### 商家端

1. 顶部独立保留微信胶囊安全行。
2. 身份摘要放在紧凑白色标题区：店铺头像、名称、审核状态、地址和身份切换。
3. 核心指标区显示钱包状态、今日单量和配送中数量；支付未开通时明确显示“未开通”，不使用虚拟金额。
4. 快捷操作使用四个等宽图标入口，重点入口“发布配送单”使用主色，其余保持中性。
5. 订单分段标签吸附在列表顶部，数量作为轻量角标。
6. 订单卡按“状态与时间—路线—骑手—费用与详情”排列，弱化非关键说明，主操作固定在右下。

### 骑手端

1. 顶部与商家端共享安全区和身份摘要结构。
2. 核心指标优先显示当前任务、可抢数量和已完成数量，刷新作为图标按钮而非独立大卡。
3. 标签分为待抢、待取货、待送达，当前标签使用底线和文字权重提示。
4. 待抢订单卡强调配送费、取送路线和隐私说明，抢单是唯一主操作。
5. 已接订单卡将联系、电话、取消等操作收敛为次级操作，将“下一状态”作为唯一主操作。
6. 权限未开通、加载、失败和空列表全部使用统一页面状态，不出现孤立大段文字。

## 二级页面

- 商家发布、订单详情、消息、钱包以及骑手钱包统一使用 `CapsulePageHeader`、共享按钮、字段、提示和状态组件。
- 页面标题与操作不进入微信胶囊占用区；底部主操作预留安全区和键盘空间。
- 表单采用分组区块与行级提示；确认、风险和禁用状态使用现有 `AppDialog`、`AppNotice` 与 `AppButton`，不调用系统样式弹窗代替业务反馈。
- 钱包未开通时保留真实功能开关状态，不展示充值入口或假账本。

## 数据与交互边界

- 保留 `useIdentityGuard` 和身份审核判断，未审核用户不得进入工作台。
- 保留现有订单接口、状态枚举、页面路由、私信会话和支付功能开关。
- 不修改服务端金额、不在客户端推导新业务状态、不创建演示订单。
- 刷新、重试、提交和状态变更继续使用既有并发锁，避免重复操作。
- 图片缺失时使用现有无图状态，不生成装饰图或替代真实素材。

## 验收标准

- 商家端和骑手端在 iPhone 15 Pro、常见 Android 比例下不与微信胶囊重叠。
- 首页首屏能清楚识别当前身份、核心数字、主要操作和当前订单状态。
- 订单卡在长地址、长店名、无骑手、支付未开通、空列表和接口失败时不溢出。
- 所有可点击区域至少 88rpx 高或提供等效触控热区。
- `npm run check:miniapp-ui`、角色业务契约、类型检查、全量 `npm run verify` 和生产构建通过。
- 不上传微信版本；最终由用户在开发者工具中编译并上传体验版。
